# Spec Delta

## ADDED Requirements

### Requirement: A single picture — a source with a frame at any duration; a missing one — a placeholder, not "Loading…"
A single image file (JPEG, PNG — including PNG with alpha, as the system FFmpeg reads it)
SHALL be a full-fledged source: it has ONE frame, returned at ANY requested tick
(there is neither a frame grid nor an end of the material — an event of any length shows the picture
in full), audio is silence, the duration is "practically infinite" (as for the placeholder),
decode scale step is taken from the native size of the picture, alpha PNG gives transparency in the composite. The frame SHALL
reach the preview no later than the video frame of the same size: the "Loading…" (a scrim of incompleteness
longer than 180 ms) over a picture event MUST NOT hang after the first read of the file.
A missing picture SHALL get the same placeholder as video (a dark frame with the
file name), and the placeholder is a FULL frame: the "Loading…" scrim over it MUST NOT appear at all;
the person sees the name of the missing file in the frame right away, not when viewing it. Picture fixtures
(JPEG, PNG with alpha) SHALL be generated by `fixtures/gen.sh` and cover reading, planning,
preview and export.
Why: R.67, the owner: "static pictures don't display at all.. there's an eternal
Loading... not only does it not work - you also find out about it only at the moment of
viewing". There was not a single fixture with pictures in the project — the path had never been under
test; note F-MED-003 measured a single PNG by hand in R.52.

#### Scenario: A picture is read, planned, shown and exported
- **WHEN** an event of 10 s on the JPEG fixture and an event on a PNG with alpha over a colored background; the frame is requested at 0, 3.7 and 9.96 s; it is opened in the harness; 1 s is exported
- **THEN** the source is open, at all three ticks the same frame with the picture's pixels; the event is present in the frame plan; in the harness the preview is complete within 180 ms (there is no "Loading…" scrim); the PNG with alpha shows the background through transparent pixels; the export contains the picture's frames (a pixel probe); determinism — byte for byte
- **PATH** drag `still.jpg` onto the timeline → the event appeared → click on it → the picture is in the preview at once, without "Loading…" → pull the edge of the event to 20 s → the picture is in place over the whole length
- **TEST** t796 (`src/libs/kt-media/tests/ffmpeg_conformance.rs`), t796b (`src/libs/kt-engine/tests/stills.rs`), t796c (`src/apps/kt-app/src/layout_tests.rs`), live scenario `src/scripts/live/stills.py`

#### Scenario: A missing picture — a stub with the name, without "Loading…"
- **WHEN** the project references a nonexistent `logo.jpg`; it is opened in the harness; the cursor is placed on the event; 500 ms pass
- **THEN** the frame holds a dark placeholder with the text `logo.jpg` (a pixel probe of the caption), the notification names the file; there is no "Loading…" scrim in any frame (on the previous code it was eternal); returning the file to its place replaces the placeholder with the picture without reopening
- **PATH** open a project without the picture → the event at once shows a dark frame with the file name, a bell with a notification → put the file back in place → the picture appeared by itself
- **TEST** t796d (`src/apps/kt-app/src/layout_tests.rs`), live scenario `src/scripts/live/stills.py`

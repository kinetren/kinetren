# Spec Delta

## ADDED Requirements

### Requirement: Кривые любого носителя показывает один виджет, паспорт цели читается по адресу

Каждый носитель кривых (слот эффекта, генератор на событии, ВЛОЖЕНИЕ с переопределениями,
переход, камера) SHALL рисовать свои кривые одним виджетом автоматизации (`automation::draw`):
график ↔ таблица, активная кривая, ключ по курсору, замок оси один на программу. Окно,
дающее править значение по времени без этого виджета, MUST NOT существовать. Паспорт
свойства по адресу (`Project::addr_spec`, зеркало `addr_type`) SHALL быть единственным
источником пределов, шага и умолчания для публикации и для окна потребителя; `match` по
владельцу исчерпывающий — новый владелец не соберётся без ветки.
Почему: «один механизм анимации на всё» (решение Р.34) — окно экземпляра его обошло и
получило скрытую запись ключей без графика (Р.60); второй источник пределов (ноль вместо
`None`) разошёлся с паспортом цели в первый же день.

#### Scenario: Носители рисуют кривые одним кодом
- **WHEN** перечисляются окна kt-app, где значение можно править по времени
- **THEN** каждое ходит через `automation::draw`; проба виджета найдена в окне слота, генератора и экземпляра ленты; прямых вызовов `bound_apply` мимо `CurveBind` вне виджета нет
- **TEST** t691 (`src/apps/kt-app/src/layout_tests.rs`), t693 (`src/apps/kt-app/src/reach_tests.rs`)

#### Scenario: Паспорт по адресу для каждого владельца
- **WHEN** запрашивается паспорт по адресу слота, генератора, атрибута клипа, перехода, камеры и вложенной публикации
- **THEN** возвращается `ParamSpec` с пределами и умолчанием цели (у вложенной публикации — сужение внешней ручки поверх паспорта её цели); у исчезнувшей цели — `None`; тип совпадает с `addr_type`
- **TEST** t694 (`src/libs/kt-model/tests/pubparam.rs`)

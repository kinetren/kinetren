# Spec Delta

## MODIFIED Requirements

### Requirement: FFmpeg — системный, загружается в рантайме, бинарь не линкуется с libav*

Декод и мукс SHALL идти через libavcodec/libavformat FFmpeg мажоров 6/7/8, УСТАНОВЛЕННОГО на
машине пользователя и загружаемого в рантайме при первом обращении: мажор определяется по
`avcodec_version()`, типы структур берутся из версионного модуля (bindgen по вендоренным
заголовкам, сгенерированный для целевой платформы). Бинарь MUST NOT линковаться с libav* и
MUST NOT тащить свою сборку FFmpeg, плагины или внешний бинарник `ffmpeg` в рантайме. Один
исполняемый файл работает на системах с любым из поддерживаемых мажоров и использует все
аппаратные ускорения того FFmpeg, что стоит на машине.

На Linux библиотеки SHALL открываться по SONAME (`libavcodec.so.62/61/60` …) от новых
мажоров к старым; согласованность набора обеспечивает `ld.so` по NEEDED. Если задан
`KINETREN_FFMPEG_DIR`, его каталог пробуется ПЕРВЫМ на обеих ОС: набор оттуда грузится по
полным путям в порядке зависимостей (ниже), а без полного набора каталог попадает в отчёт
отвергнутым, и поиск идёт дальше обычным путём.

На Windows системного FFmpeg нет, поэтому загрузчик SHALL искать КАТАЛОГ с полным набором
`avutil-N.dll`, `swresample-N.dll`, `swscale-N.dll`, `avcodec-N.dll`, `avformat-N.dll`
одного мажора (8: 60/6/9/62/62; 7: 59/5/8/61/61; 6: 58/4/7/60/60) в фиксированном порядке:
(1) каталог, выбранный пользователем (сохранён в настройках); (2) `KINETREN_FFMPEG_DIR`;
(3) `ffmpeg\` и `ffmpeg\bin\` рядом с исполняемым файлом; (4) собственный каталог загрузки
Kinetren; (5) каталоги `PATH`, где лежит такой набор, — а если в каталоге `PATH` лежит
только `ffmpeg.exe`, являющийся ссылкой (winget `Links`), то каталог её цели; (6) известные
места установки (scoop `ffmpeg-shared`, пакеты winget `Gyan.FFmpeg.Shared` и
`BtbN.FFmpeg.*Shared*`, `C:\ffmpeg\bin`, `%ProgramFiles%\ffmpeg\bin`). Порядок каталогов
важнее мажора: выбор пользователя побеждает более новый мажор в другом месте. Внутри
каталога мажоры перебираются от 8 к 6. Все пять библиотек MUST грузиться по ПОЛНОМУ пути из
ОДНОГО каталога в порядке зависимостей (avutil → swresample → swscale → avcodec → avformat),
чтобы импорты связывались с уже загруженными модулями этого каталога, а не с одноимённой
DLL из другого места `PATH`; после загрузки каждый модуль MUST находиться в выбранном
каталоге, иначе набор отвергается.

Неудачная загрузка MUST NOT запоминаться до конца процесса: следующее обращение после
явного «пересканировать» (или после установки/загрузки) ищет заново; удачная загрузка
запоминается навсегда.
Почему: прямое требование владельца («никакой своей сборки FFmpeg и никаких плагинов»);
линковка привязывала бинарь к мажору машины сборки (`libavcodec.so.60: cannot open shared
object file` на системе с FFmpeg 7). На Windows `LoadLibrary` по голому имени системного
FFmpeg не найдёт — его там не бывает, а DLL разных программ на `PATH` легко смешиваются
(«DLL hell»): загрузчик Windows сопоставляет зависимости по базовому имени, и `avcodec`
из одного каталога связался бы с `avutil` той же мажорной версии, но чужой минорной из
другого. winget кладёт в `PATH` не каталог пакета, а ссылку на `ffmpeg.exe`, и без
разыменования DLL рядом не найти. Запомненная ошибка требовала бы перезапуска после
установки FFmpeg — ровно в тот момент, когда пользователь только что сделал то, о чём его
попросили.

#### Scenario: Conformance источника на реальных фикстурах
- **WHEN** открывается FLAC/AAC/H.264/VP9/муксованный файл
- **THEN** burst после seek байт-в-байт равен декоду с нуля (lossless), 44.1 kHz даёт правильную длину на 48 kHz, backward seek H.264 и seek VP9 детерминированы, keyframe-индекс и лестница качеств работают
- **TEST** t10 (`src/libs/kt-media/tests/ffmpeg_conformance.rs`)

#### Scenario: Спан-декод равен покадровому и не пересоздаёт декодер
- **WHEN** сетка ключей читается одним forward-проходом
- **THEN** каждый ключ закрыт кадром, кадры байт-в-байт равны покадровому чтению, reopens ≤ 1, каждый кадр декодирован один раз; выбор кадра при несовпадающих сетках — floor и только floor
- **TEST** t21, t112 (`src/libs/kt-media/tests/ffmpeg_conformance.rs`)

#### Scenario: Счётчики I/O живые
- **WHEN** файл открывается и читается
- **THEN** opens/packet_reads растут — перф-панель не показывает мёртвых нулей
- **TEST** t37 (`src/libs/kt-media/tests/ffmpeg_conformance.rs`)

#### Scenario: Муксер не роняет кадры (контейнер: capability `export`)
- **WHEN** экспорт 60 кадров через libx264 с send-retry при EAGAIN
- **THEN** в файле РЕАЛЬНО 60 кадров, подсчитанных собственным декодером
- **TEST** t33 (`src/libs/kt-engine/tests/export_options.rs`)

#### Scenario: Релизный бинарь не линкован с libav*
- **WHEN** собирается релизный тарбол (Linux) или zip (Windows)
- **THEN** на Linux `ldd … | grep -c libav` даёт 0; на Windows таблица импорта PE у `kinetren.exe` и `kt-cli.exe` не называет ни одной `av*`/`sw*` DLL и ни одной DLL рантайма mingw (`libgcc_s*`, `libstdc++*`, `libwinpthread*`); иначе сборка отвергается
- **TEST** сторож в `src/scripts/release-build.sh` (правило инварианта 10 корневого CLAUDE.md)

#### Scenario: Порядок поиска на Windows и имена DLL по мажорам
- **WHEN** план поиска строится по подставным окружению и файловой системе: выбранный каталог, переменная, каталог рядом с exe, каталог загрузки, `PATH` из трёх каталогов, известные места; полный набор 8 лежит в известном месте, полный набор 7 — в выбранном каталоге
- **THEN** выбран каталог пользователя с мажором 7; имена пяти DLL каждого мажора совпадают с таблицей требования; порядок загрузки внутри набора — avutil, swresample, swscale, avcodec, avformat; функция плана чистая и проверяется на любой ОС
- **TEST** t843 (`src/libs/kt-ffmpeg/tests/loader_plan.rs`)

#### Scenario: Отвергнутые каталоги названы с причиной; ссылка winget разыменована
- **WHEN** в `PATH` есть: каталог со статическим `ffmpeg.exe` без DLL; каталог `WinGet\Links` со ссылкой `ffmpeg.exe` на пакет, где лежит полный набор 8; каталог с `avcodec-63.dll` (FFmpeg 9); каталог, где есть `avcodec-62.dll`, но нет `avutil-60.dll`
- **THEN** выбран каталог цели ссылки; отчёт перечисляет каждый отвергнутый каталог с причиной («статическая сборка — нет DLL», «FFmpeg 9 (avcodec-63) не поддерживается», «нет avutil-60.dll»)
- **TEST** t844 (`src/libs/kt-ffmpeg/tests/loader_plan.rs`)

#### Scenario: Набор грузится из одного каталога (Windows)
- **WHEN** на Windows (или под wine) загружается закреплённая сборка gyan.dev 8.1.2 из каталога, а в `PATH` раньше стоит каталог с другим `avutil-60.dll`
- **THEN** загрузка удаётся, `avcodec_version()` даёт мажор 62, и путь каждого из пяти модулей лежит в выбранном каталоге; без закреплённой сборки на машине тест пропускается с названной причиной
- **TEST** t845 (`src/libs/kt-ffmpeg/tests/loader_windows.rs`)

#### Scenario: Неудача не запоминается, удача — навсегда
- **WHEN** первая загрузка идёт при пустом списке каталогов, затем добавляется каталог с полным набором и вызывается пересканирование, затем пересканирование вызывается снова
- **THEN** первая загрузка — ошибка с отчётом поиска; вторая — успех; третья возвращает тот же загруженный набор, не открывая библиотек повторно
- **TEST** t846 (`src/libs/kt-ffmpeg/tests/loader_plan.rs`)

## ADDED Requirements

### Requirement: Загрузка закреплённой сборки FFmpeg изнутри программы (Windows)

На Windows программа SHALL предлагать загрузку FFmpeg одной кнопкой. Загружается ровно
одна ЗАКРЕПЛЁННАЯ сборка: `ffmpeg-8.1.2-full_build-shared.7z` с
`https://www.gyan.dev/ffmpeg/builds/packages/`. Архив MUST сверяться с SHA-256, записанным в
исходниках программы; ссылка «последний релиз» (`ffmpeg-release-full-shared.7z`) MUST NOT
использоваться. Из архива SHALL извлекаться только `bin/*.dll` и файл лицензии, в
`%LOCALAPPDATA%\kinetren\ffmpeg\8.1.2\`. Каталог MUST появляться только целиком: распаковка
идёт во временный каталог, который переименовывается в конечный. Загрузка SHALL начинаться
только по нажатию пользователя, после показа источника и лицензии (GPLv3, сборка gyan.dev),
и идёт фоновой задачей с прогрессом и отменой. Отмена, обрыв или несовпадение хэша MUST
оставлять каталог загрузки без следов. После успешной установки загрузчик пересканирует
каталоги, и медиа, показанные заглушками, восстанавливаются тем же путём, что при
возвращении пропавшего файла. Ничего не скачивается автоматически.
Почему: решение владельца (2026-10-22): «п.1 + сделать возможность скачивания с gyan.dev
shared сборки». Закрепление версии нужно потому, что «последний релиз» gyan.dev уже FFmpeg
9.0.2, который загрузчик не поддерживает, и кнопка, которая скачала бы неподходящую
библиотеку, хуже, чем никакая. Хэш в своих исходниках, а не соседний `.sha256` с того же
сервера: проверка против того же источника ничего не доказывает. Мы не распространяем
FFmpeg сами (ни своей сборки, ни DLL в zip): пользователь получает сборку от её автора
под её лицензией.

#### Scenario: Проверка, распаковка и атомарная установка
- **WHEN** загрузчик получает с локального тестового сервера маленький 7z-архив той же структуры (`<корень>/bin/*.dll`, `<корень>/LICENSE`, `<корень>/bin/ffmpeg.exe`, `<корень>/include/…`), сначала с неверным хэшем, затем с верным; затем загрузка отменяется на середине; затем сервер рвёт соединение
- **THEN** при неверном хэше каталог загрузки пуст и ошибка называет ожидаемый и полученный хэш; при верном появляется `8.1.2\` только с DLL и лицензией (без exe и include), а временных каталогов нет; отмена и обрыв оставляют каталог загрузки пустым
- **TEST** t847 (`src/apps/kt-app/src/ffmpeg_setup.rs`)

### Requirement: Отчёт поиска FFmpeg виден человеку и kt-cli

Результат поиска FFmpeg SHALL быть доступен как отчёт: выбранный каталог (или SONAME на
Linux), мажор и полная версия avcodec, и каждый отвергнутый кандидат с причиной. GUI
показывает его в окне FFmpeg; `kt-cli ffmpeg` печатает его и завершается с ненулевым кодом,
если FFmpeg не загружен. Текст ошибки «FFmpeg не найден» MUST подсказывать способ своей ОС:
на Linux — пакеты дистрибутива, на Windows — кнопку загрузки или установку shared-сборки
поддерживаемого мажора.
Почему: на Windows причин неудачи несколько, и они неочевидны (статическая сборка, FFmpeg 9,
смешанный набор). Без названной причины пользователь видит одни заглушки и не знает, что
делать.

#### Scenario: kt-cli печатает отчёт
- **WHEN** `kt-cli ffmpeg` запускается с `KINETREN_FFMPEG_DIR`, указывающим на пустой каталог, и с FFmpeg, доступным обычным путём; затем без доступного FFmpeg
- **THEN** в первом случае вывод называет пустой каталог отвергнутым («нет avcodec-*.dll»), выбранный кандидат и его версию, код 0; во втором — список отвергнутых и подсказку своей ОС, код ненулевой
- **TEST** t848 (`src/apps/kt-cli/tests/cli.rs`)

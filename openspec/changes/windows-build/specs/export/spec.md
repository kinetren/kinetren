# Spec Delta

## MODIFIED Requirements

### Requirement: Экспорт полностью внутрипроцессный, энкодер выбирается открытием

Мукс и кодирование SHALL идти через libavformat/libavcodec FFmpeg, установленного на машине
и загруженного в рантайме (capability `media-index`): ни временных файлов, ни внешнего
бинарника `ffmpeg`, ни mkfifo. Видео-энкодер SHALL выбираться перебором кандидатов с
РЕАЛЬНОЙ проверкой открытия (`avcodec_open2`) в том же процессе, который пишет файл.
Список кандидатов зависит от ОС: на Linux
`h264_nvenc → h264_vaapi → h264_qsv → libx264 → mpeg4`, на Windows
`h264_nvenc → h264_amf → h264_qsv → libx264 → h264_mf → mpeg4`. `h264_qsv` SHALL
открываться с форматом пикселей NV12 (конверсия swscale), а не YUV420P. Каждый кандидат
SHALL получать свою настройку качества (CRF/CQ/QP/глобальное качество — по виду энкодера).
Явно затребованный энкодер MUST либо открыться, либо дать ошибку экспорта — тихой подмены
нет. Имя фактического энкодера SHALL сообщаться в статистике экспорта. Кадры MUST NOT
теряться на backpressure энкодера: при EAGAIN отправка повторяется.
Почему: наличие энкодера в сборке не значит, что он заработает (nvenc без libcuda падает),
а кэшируемого «вердикта о годности» у нас нет — значит, нечему разойтись с реальностью.
На Windows VAAPI нет; AMD и Intel без своих энкодеров в списке скатывались до `mpeg4`,
если в сборке FFmpeg нет libx264 (LGPL-сборки). `h264_mf` (Media Foundation) есть на любой
Windows, но качество у него хуже, чем у libx264, поэтому он идёт после libx264. QSV с
YUV420P не открывался вообще.

#### Scenario: Автовыбор и принудительный энкодер
- **WHEN** экспорт запускается без указания энкодера / с `libx264` / с несуществующим именем
- **THEN** авто выбирает открывшийся кандидат; `libx264` выбран ровно он и файл читается собственным декодером; неизвестное имя — явная ошибка, файла нет
- **TEST** t25 (`src/libs/kt-engine/tests/export_options.rs`)

#### Scenario: В файле все кадры
- **WHEN** экспортируется 60 кадров при 30 fps
- **THEN** движок отдал 60 кадров И в файле, прочитанном собственным декодером по всем ключам сетки, декодировано не меньше 60
- **TEST** t33 (`src/libs/kt-engine/tests/export_options.rs`), t10 (`src/libs/kt-media/tests/ffmpeg_conformance.rs`) — собственный декодер годится верификатором, потому что его seek sample-accurate

#### Scenario: Отмена и ошибка не оставляют частичного файла
- **WHEN** экспорт отменён или упал посреди видео-/аудио-фазы
- **THEN** муксер закрывается, частичный файл удаляется, результат — `Cancelled` либо ошибка
- **TEST** t25 семейство (`src/libs/kt-engine/tests/export_options.rs`) — принудительная ошибка энкодера не оставляет файла; путь отмены — `export_mp4_with_backends` (`src/libs/kt-engine/src/export.rs`)

#### Scenario: Список кандидатов и их настройки по ОС
- **WHEN** список кандидатов и настройки открытия строятся для Linux и для Windows (чистая функция, проверяется на любой ОС)
- **THEN** порядок совпадает с требованием для каждой ОС; `h264_vaapi` есть только в списке Linux, `h264_amf` и `h264_mf` — только в списке Windows; у `h264_qsv` формат пикселей NV12; у каждого кандидата есть настройка качества
- **TEST** t857 (`src/libs/kt-ffmpeg/tests/encoders.rs`)

### Requirement: Golden-эталоны сырых потоков

Функции сырых потоков (`render_raw_audio`/`render_raw_video`) SHALL отдавать аудио f32
48 kHz/2ch и RGBA-кадры колбэкам ДО муксера; их хэши MUST быть байт-в-байт равны между
прогонами на любой платформе и закоммиченным `GOLDEN_AUDIO`/`GOLDEN_VIDEO` КАЖДОЙ
поставляемой платформы (таблица по `(os, arch)`: linux/x86_64, windows/x86_64); титровая
сцена — своему `GOLDEN_TITLE_VIDEO` из той же таблицы. Проверки хэшей, которые сегодня не
ограничены платформой и отличаются между ОС только через libm (видео-FX, тумбы FX, слияние
гео-серий), SHALL пользоваться той же таблицей. На платформе, которой нет в таблице,
сравнение с константой пропускается с названной причиной, а проверка между прогонами
остаётся. Эталон меняется ТОЛЬКО осознанным решением с записью причины и прежнего значения
рядом с константой (для титра — ещё и в `FONT-MANIFEST.txt`); в эталонных проектах нет
нетто-зума и натив синтетики меньше Quality, поэтому ступень декода там ≡ 1 и новые
механизмы обязаны оставлять эталон на месте. Константа новой платформы заносится после
первого зелёного прогона на ней, с записью, на какой машине и каком прогоне она снята.
Почему: эталон — единственный сторож детерминизма (инвариант 11) сразу для аудио-микса,
варпа, переходов, композита и SIMD-ядер; байты выходного .mp4 у двух пользователей
одинаковыми не будут никогда (энкодер — свойство машины), поэтому хэшируется поток ДО
энкодера. Трансцендентные функции (`sin`, `exp`, `powf`) берутся из libm платформы
(glibc на Linux, CRT mingw на Windows) и могут разойтись в последнем бите: одна константа
на все ОС сделала бы Windows вечно красным, а её отсутствие — несторожимым.

#### Scenario: Детерминизм и эталон
- **WHEN** golden-проект рендерится дважды
- **THEN** хэши аудио и видео совпадают между прогонами (120 000 аудио-кадров, 75 видео-кадров) и равны закоммиченным константам своей платформы (linux/x86_64, windows/x86_64)
- **TEST** t11_streams_are_deterministic_across_runs, t11_streams_match_committed_golden (`src/libs/kt-engine/tests/golden_export.rs`)

#### Scenario: Титровый эталон отдельный и не двигается
- **WHEN** титровая сцена рендерится дважды / параметры титра переехали на событие
- **THEN** хэш стабилен и равен `GOLDEN_TITLE_VIDEO` своей платформы; перенос значений эталон не сдвинул
- **TEST** t485_title_export_is_deterministic, t485_title_matches_committed_golden, t662 (`src/libs/kt-engine/tests/title_golden.rs`)

#### Scenario: У каждой поставляемой платформы есть свои константы
- **WHEN** таблицы эталонов (экспорт, титр, видео-FX, тумбы FX, слияние гео-серий) читаются сторожем
- **THEN** у каждой платформы из списка поставки (linux/x86_64, windows/x86_64) есть запись в каждой таблице, и у каждой записи есть строка происхождения (машина, прогон); на платформе без записи тест сравнения пропускается с названной причиной, а не проходит молча
- **TEST** t858 (`src/libs/kt-engine/tests/golden_export.rs`)

# kt-app (eframe/egui GUI)

UI-инварианты, выстраданные раундами 4–5 (детали и номера тестов — docs/porting-notes.md 38–94). Нарушение любого — регрессия производительности или UX.

## Перерисовка и стоимость кадра (пп. 38–40, 53, 57)

- **`animating` = «что-то ДВИЖЕТСЯ», а не «что-то горит».** Любое новое анимируемое состояние обязано затухать/сходиться и отпускать repaint в idle (250 мс). Урок: `MeterState::is_active()` по условию «бар выше минимума» залипал навсегда после первого звука → вечные 60 fps в простое, грелась ВСЯ система (t38, t20-repaint).
- **Ключ кадра превью — тик, ВЫРОВНЕННЫЙ по сетке fps** (`preview_key_tick`), никогда не сырой. Сырой тик менялся каждый UI-кадр → полный перекомпозит + перезаливка текстуры в GPU 60 раз/с (до ~500 МБ/с на 1080p) — «визуально нет 30 fps» при «FPS=60» (t39).
- **Никаких аллокаций/клонов структур в draw-путях на кадр.** Снапшоты для кадра — `Arc`-клоны кэшей по ревизии (coverage/имена/пути, model_rev / cache.epoch). Буфер композиции превью переиспользуется (`compose_preview_into`); glow-мип — каждый 4-й новый кадр.
- **Тысячи painter-примитивов = меш.** Волноформа была 2 `line_segment` на ПИКСЕЛЬ; glow метров — ~310 тессилируемых эллипсов за кадр. И то и другое — один `Mesh` (t40).
- **`cache.epoch()` меняется КАЖДОЙ вставкой** — при воспроизведении это шторм. Любой UI-кэш, инвалидируемый по epoch, при игре обязан троттлиться (coverage-полоски — не чаще 4 Гц; иначе 60 опросов/с под мьютексом кэша, контеншен с декодерами).
- **Честные метрики прежде фикса**: V-fps (показанные НОВЫЕ кадры) и «V-пропущено ячеек» в перф-панели. Именно они диагностировали квант-потолок 24 fps с машины пользователя. «FPS» — это ui-кадры, о видео он не говорит НИЧЕГО.

## Часы показа видео (пп. 55–56 — главный урок раунда 5)

- **Playhead двигается КВАНТАМИ аудио-колбэка** (PipeWire нередко 2048 сэмплов = 42.7 мс). Любой потребитель позиции для ПОКАЗА обязан ходить через `Player::video_playhead()` (интерполяция `display_extrapolation` + сглаженная latency), а не читать `transport.playhead()` при игре. Без этого видео физически не может показать больше 1000/квант кадров/с — наблюдались ровно 24, независимо от качества/бэкенда/экономного режима (t56).
- **Сырая `output_latency` дрожит между колбэками на ±кадр** — читать `latency_smooth` (EMA в render-потоке), плюс монотонный кламп ключа при игре (откат ≤2 ячеек игнорируется; loop-wrap/seek проходят).

## GPU/платформа (пп. 39, 53)

- wgpu-дефолт `PowerPreference::HighPerformance` берёт дискретную карту → на гибридной графике PRIME-копирование каждого кадра тормозит ВСЮ систему. Дефолт — LowPower, `WGPU_POWER_PREF` переопределяет; `WGPU_BACKEND=gl` — обход Vulkan. Активный адаптер показан в перф-панели («GPU: …»).
- Софт-рендер детектится по adapter info; тяжёлые glow при нём отключены.

## DnD файлов (пп. 47, 52)

- **winit 0.30/X11 НЕ отдаёт позицию мыши при перетаскивании файла** (координаты XdndPosition выброшены, движение не шлётся) — позиция читается напрямую из X-сервера (x11rb `QueryPointer`, physical px → points через pixels_per_point). Wayland file-DnD в winit отсутствует → честный fallback на playhead.
- Пер-кадровые состояния (`dnd_hover`) не стирать безусловным `take()`: позиция живёт, пока идёт hover, и забирается ТОЛЬКО при дропе (`dnd_keep_hover`, регресс в t47).

## Мультивьюпорт (п. 51)

- Деатач превью — `show_viewport_immediate` (deferred требует `Send+Sync`, с `&mut self` не совместим). Один `egui::Context` на все вьюпорты — `TextureHandle` работает в чужом окне.
- `ctx.input()` внутри вьюпорта — input ЭТОГО вьюпорта: шорткаты дублируются вызовом handle_keys из окна; Esc окна превью скоупится локально (не дёргает глобальный Esc-каскад).
- Foreground-оверлеи с rect'ами чужого вьюпорта в главном окне не рисовать.

## Синхронизация с плеером

- **Всё, что синхронизируется с плеером «при изменении», обязано синхронизироваться и при ОТКРЫТИИ проекта.** Урок (п. 54): loop-регион передавался только из `on_region_changed` — загруженный файл с loop играл линейно мимо региона.

## Геометрия таймлайна

- Маппинг позиций вне draw_timeline — только через `TlGeom` (кэш кадра, display-строки `lane_order`); формулы «offset(kind)+lane» вне TlGeom не заводить (t47/t50).

## Отладочные env

- `KT_AUTOPLAY=1` — играть сразу после открытия (перф-замеры без ввода).
- `KT_DETACH_PREVIEW=1` — старт с отделённым превью.
- `KT_DECORATIONS=1` — вернуть WM-декорации окна (фолбэк для капризных WM; штатно окно borderless, тулбар = титлбар, ресайз — зоны `resize_zone` по периметру).
- **Shift+колесо в egui приходит как scroll.x** (smooth_scroll_delta) — вертикальные жесты таймлайна читают сырые `Event::MouseWheel` с модификаторами (п.12 р.6); пан-ветка гейтится «без Shift».

## UI-тексты (п.17/21/25 р.7 — требование пользователя)

- **Очевидных надписей НЕ делать.** Значение с единицей само себя объясняет: «100 px/s», «1280×720», «30» в комбо FPS — без префиксов «зум:», «Разрешение:», «FPS:». Состояние, видимое подсветкой кнопки (Loop) или самим значением, не дублировать текстом («(loop)», «(стоп)», «≠1×»).
- Все подсказки — через `KtApp::hint()` (попап + правый низ статусбара), не голый `on_hover_text`.

## X11 StartDrag/BeginResize (п.28 р.7)

- `_NET_WM_MOVERESIZE` забирает указатель у приложения: ButtonReleased НЕ приходит, egui вечно держит `dragged`, и у ВСЕГО остального UI пропадает hovered (скролл/ховеры мертвы до следующего клика). После каждого `send_viewport_cmd(StartDrag|BeginResize)` обязателен `KtApp::release_pointer_after_wm_grab` (ctx.stop_dragging + сброс pointer).
- Гейты «мышь над виджетом» для колеса — `contains_pointer()` + `i.pointer.hover_pos()`, НЕ `response.hover_pos()` (тот подавляется чужим активным драгом).

## Тумбы и sidecar-БД (п.1/п.14 р.7)

- Ключи `thumbnails` — точный PK (media, t): «ближайший» кадр только через `MediaIndexDb::thumbnail_near` (бин-скраб переиспользует тумбы филмстрипа). `ThumbKey` не расширять (общий кэш бин↔таймлайн, тест 62) — допуск near передаётся параметром очереди.
- Всё, что может «не получиться» у воркера (длительность, декод ключа), обязано публиковать НЕУДАЧУ (durations=None / failed-set) — иначе UI перезаказывает на каждом кадре и счётчик FFmpeg-open взлетает пропорционально FPS интерфейса.

## Панели не должны раздуваться контентом (регрессия р.7.1 п.3)

- `Panel::left/right` в этом форке отдаёт панели ширину ПО КОНТЕНТУ, если контент требует больше: `ScrollArea::auto_shrink([false, ..])`, `ui.set_min_width(available)`, `Grid` с `TextWrapMode::Extend` и фиксированные `set_width` внутри — все давят на панель. Симптом: левая колонка расползается и центральная область (превью) схлопывается в ничто — «превью пропало вникуда».
- Правила: по ширине — `auto_shrink([true, _])`; многоколоночные метрики — `ui.columns` (делит доступную ширину) + `Truncate`, НЕ `Grid` с Extend; карточки бина — ширина `available.clamp(min, PREVIEW_W)`; страховка — `Panel::max_size`.

## UI/UX делается ДЛЯ ПОЛЬЗОВАТЕЛЯ (требование п.17 р.8, ужесточено п.11 р.11 — читать первым)

Правило появилось после трёх раундов, где интерфейс «компилировался и рисовался», но им нельзя было пользоваться, и переписано в чек-лист после того, как пользователь В ПЯТЫЙ РАЗ прислал замечания про одни и те же подходы. Если ты пишешь код UI и не прогнал этот список — пункт не закрыт, чем бы ни был зелёный `cargo test`.

### Чек-лист перед закрытием ЛЮБОГО UI-пункта

1. **Попал мышью с первого раза?** Проделай действие как человек: навёл, нажал, потянул, отпустил, нажал ещё раз. Если нужно целиться — дефект, даже когда «функция работает». Хват-зона может и должна быть шире рисунка: кромки окна 8 px, углы 16 px, сепараторы `resize_grab_radius_side = 8`, фейдер шире виджета. Визуал при этом не меняется.
2. **Работает во время ВОСПРОИЗВЕДЕНИЯ?** Гейт «только на паузе» ставится, лишь если без него ломается инвариант движка, а не «чтобы не думать». Плеер умеет seek на ходу; окно ввода, поиск, метки, навигация обязаны работать при игре.
3. **Ничего не скачет?** Ширина/высота/раскладка не меняется при переключении режима, открытии поля ввода, смене текста или числа. Ширину фиксируй галлеей самого длинного варианта, а не «примерным» числом.
4. **Умолчание — полезное.** Полезный режим включён по умолчанию, модификатор его ВЫКЛЮЧАЕТ (магнит, а не «зажми, чтобы примагнитить»). Пользователь не должен настраивать программу, чтобы она вела себя нормально.
5. **Действие не гасит соседнее состояние.** Снятие региона не выключает loop, автосейв не гасит звёздочку, смена режима не теряет раскладку. Побочные эффекты «за компанию» — дефект.
6. **Есть предел.** У всего, что тянется мышью, есть min И max (панель метров, ширина колонки, зум). «Растянул на пол-экрана» — это про отсутствующий `max_size`.
7. **Текст помещается.** Длинное имя не вылезает за свою зону и не наезжает на чужую: меряй `layout_no_wrap` + `galley.size()` и решай (усечь с многоточием / ярлык с подложкой / перенести), а не надейся на «обычно короткое».
8. **Виджет вписан в программу, а не «поставлен».** Стандартный `TextEdit`/`Slider`/`ComboBox` посреди фирменного тулбара — халтура: ввод рисуется в том же прямоугольнике и тем же шрифтом, что и заменяемое им значение. Пользовательская формулировка: «нельзя тупо херачить туда inputfield».
9. **Ничего лишнего не появилось.** Никаких чекбоксов «не к месту» (режимы — иконкой, как в файловых менеджерах), никаких очевидных надписей («зум:», «FPS:»), никакого дублирования текстом того, что видно подсветкой кнопки.
10. **Подсказка ровно одна и в одном месте** (п.14 р.8): правый низ строки состояния через `KtApp::hint()`, приоритет наведение → режим → сообщение → дежурная строка. Всплывающих попапов и оверлеев-инструкций в программе нет.
11. **Непечатные символы проверены по шрифту** — см. отдельный раздел ниже. Квадрат-заглушка у пользователя = не проверил.
12. **Фоновая работа не мешает.** Автосейв/перезаказ тумбов/инвалидация кэшей не делаются во время жеста или воспроизведения и не дёргают интерфейс чаще, чем нужно человеку.

### Как читать замечания пользователя

- **Замечание — это КЛАСС проблем, а не один случай.** Он приводит один-два примера («иконка диагностики не в тему», «имя дорожки вылезает»), а в программе таких мест обычно больше. Прошёлся по одной иконке — проверь ВЕСЬ набор (так нашлись сразу два неверных глифа); поправил одну подсказку — вычисти все попапы; починил ширину одной панели — проверь остальные.
- **Повторное замечание = правило не записано.** Если пользователь пишет про то же самое второй раз — сначала внеси правило сюда, потом чини код.
- **Неясно — спроси СРАЗУ**, до реализации, а не выдавай догадку за решение. Один вопрос дешевле переделки раунда.

### Правки содержимого ≠ правки удобства (п.5 р.11)

- «Содержимое» — клипы, FX, morpher, метки, дорожки, медиа: только они поднимают `dirty_content`, только от них звёздочка в заголовке и только они запускают автосейв.
- «Удобство» — регион, loop, зум, скролл, курсор, раскладка бина, имена дорожек, порядок строк: поднимают `dirty_ui`, сохраняются попутно с любой записью проекта и при выходе, но НИКОГДА не делают вид, что пользователь что-то изменил.
- Новый флаг «что-то поменялось» не заводить: любое новое состояние обязано попасть ровно в одну из двух корзин.

## Правило тестирования вёрстки (требование п.9 р.8)

- Любое изменение вёрстки или интерактивного поведения сопровождается harness-тестом в `apps/kt-app/src/layout_tests.rs` (egui_kittest прогоняет настоящие кадры без окна и GPU): ширина панели, перетаскивание сепаратора, курсор на кромке, отправка `BeginResize`, кликабельность кнопки, «превью не схлопнулось».
- Скриншот — дополнение, а не доказательство: все три прошлые поломки прекрасно «выглядели» на картинке.
- Отладка «кто съел клик» — `KT_DEBUG_HITS=1` (штатная подсветка egui).
- **Драг в харнессе повторяется В ТРИ ШАГА**: нажать → сдвинуть на ~8 px → вести дальше. egui признаёт драг начавшимся только после порога, и код читает позицию указателя ИМЕННО в этом кадре: если тест прыгает из точки захвата сразу в цель, смещение захвата вычисляется уже в цели и объект стоит на месте — тест «зелёный на сломанном коде» или наоборот. Так же ведёт себя человек, поэтому это не костыль теста.
- **Тест обязан падать на старом коде.** Прежде чем считать регресс-тест написанным, временно верни прежнюю формулу и убедись, что он краснеет (для t95 старый код давал 93910 вместо 90000). Тест, который зелен и до, и после, не проверяет ничего.
- Панель в egui 0.36 растёт под контент: её ФАКТИЧЕСКИЙ край (`PanelState::outer_rect`) может не совпадать с запрошенной шириной, и тогда сепаратор «уезжает» от границы. Тест обязан брать `outer_rect`, а контент — не толкать панель (см. раздел «Панели не должны раздуваться контентом»).

## Порядок панелей решает (п.1 р.9 — стоило трёх раундов)

- Всё, что НАПОЛНЯЕТСЯ во время кадра (`hover_hint`), нельзя читать в панели, нарисованной раньше источников. Статусбар — вторая панель кадра, а кнопки рисуются позже: подсказок не было видно вообще, кроме колокольчика (он внутри самого статусбара). Такие строки рисуются в КОНЦЕ кадра отдельным слоем (`Area(Foreground).interactable(false)` — иначе слой крадёт драг окна).
- Тест обязан проверять ОТРИСОВАННОЕ (`status_line_shown`), а не внутреннее поле: `hover_hint` после кадра уже заполнен, и тест зеленеет при мёртвой фиче.
- Корневой `Ui` от eframe обрамлён дефолтными 8 px — из-за них весь интерфейс не доходил до краёв окна («отступ метров справа»). Рисуем на полном `ctx.content_rect()`.

## Численная устойчивость UI-анимаций (п.7 р.9 — дефект «больно по ушам»)

- `stable_dt` НЕ равен 1/60: после простоя он приходит равным задержке idle-перерисовки (до 250 мс, кламп 0.1 с), а экономный режим даёт 33 мс. Явные схемы интегрирования на таких dt расходятся: анимация фейдера улетала на 400 dB за три кадра.
- Для подъезда к цели использовать аналитическое решение (экспонента) или экспоненциальное сглаживание — они не расходятся ни при каком dt; тест обязан гонять ПЛОХИЕ dt (0.1, 1/30, чередование), а не только 1/60.
- Всё, что уходит в звук, клампится В ДВИЖКЕ (`set_master_gain` — потолок +24 dB, гашение NaN/inf): движок не должен зависеть от корректности UI.

## Иконка и таскбар (п.6 р.9)

- `with_icon` обязателен, иначе у окна нет иконки вовсе. На X11 winit НЕ выставляет app_id — WM_CLASS равен имени бинаря (`kt-app`), поэтому `StartupWMClass` в `.desktop` должен совпадать именно с ним, иначе таскбар не связывает окно с иконкой. `with_app_id` нужен для Wayland.

## Единицы времени: playhead живёт в АУДИОКАДРАХ (п.7 р.10)

- `Transport` хранит позицию в кадрах 48 кГц, а модель — в тиках 90 кГц. Round-trip «тик → кадр → тик» **усекает вниз** и точен только на тиках, кратных 15. Любая навигация вида «строго правее текущей позиции» обязана работать на выровненных значениях (`Tick::align_audio_up`), иначе курсор после перемотки оказывается на тик левее цели и кнопка молча застревает на одной точке — ровно так «Вперёд» не работала, пока «Назад» работала (усечение вниз ей помогало).
- «Конец» для навигации — не только конец материала: маркер или граница региона могут лежать правее, и тогда упор в конец утаскивает курсор назад.

## Непечатные символы обязаны быть в шрифтах (п.6 р.10, правило и тест — п.12 р.11)

- Программа грузит РОВНО четыре шрифта (`install_fonts`): Ubuntu-Light, NotoEmoji, emoji-icon-font (дефолт egui) и вендоренный Phosphor. Чего в них нет — egui рисует квадратом-заглушкой, и это видит пользователь. Так в интерфейс попали `●` U+25CF (индикатор изменений), `≡` U+2261 (кнопка меню узкого тулбара) и `✓` U+2713 (галка в пункте «Реверс»).
- **Правило: любой символ вне ASCII/кириллицы берётся из Phosphor** (`icons.rs`, кодпоинты PUA) либо рисуется вектором (как кнопки окна). «Похожий юникодный символ» не подставлять — сначала проверь.
- **Тест 100 (`font_tests.rs`) проверяет это автоматически**: сканирует исходники kt-app, достаёт содержимое строковых и символьных литералов (раскрывая `\u{...}`, которыми записаны иконки), и требует глиф для каждого неASCII-символа. Тестовый код исключён (текст ассертов пользователь не видит) — тестовый модуль в файле обязан начинаться строкой `#[cfg(test)]` с НУЛЕВЫМ отступом, иначе сканер его не отрежет.
- Кодпоинт нового глифа Phosphor ищется по таблице лигатур GSUB (post-имён в шрифте нет):
  ```python
  from fontTools.ttLib import TTFont
  f = TTFont('apps/kt-app/assets/Phosphor.ttf'); cmap = f.getBestCmap()
  g2c = {}; [g2c.setdefault(g, cp) for cp, g in cmap.items()]
  for lk in f['GSUB'].table.LookupList.Lookup:
      for st in lk.SubTable:
          for first, ligs in getattr(st, 'ligatures', {}).items():
              for l in ligs: print(first + ''.join(l.Component), hex(g2c.get(l.LigGlyph, 0)))
  ```
  Имена в лигатурах — с `hyphen` вместо дефиса (`lockhyphensimple` = `lock-simple`).

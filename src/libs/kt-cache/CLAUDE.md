# kt-cache

Кэш burst'ов + coverage. Без FFmpeg/аудио-железа.

## Инварианты
- Кэш — ЕДИНСТВЕННАЯ правда о coverage (инвариант №4 корневого CLAUDE.md). Никаких параллельных структур «прогретости» — старые ms-бакеты (дефект g) врали четырьмя способами.
- Quality — часть ключа; audio-ключ качества не имеет.
- Coverage — interval-set, обновляемый на insert/evict; запрос O(log n), без сэмплирования.
- Pin (loop-регион) исключает записи из eviction, но не из coverage.
- Кэш хранит ПРЕ-FX данные; coverage-полоски строятся ТОЛЬКО по ним. Аудио-пост-FX не кэшировать (FX дешевле декода). ВИДЕО-пост-FX (р.7 п.2) — отдельный kind `PostFxVideo{quality, fx_hash}` (idx = таймлайн-тик): чистая мемоизация дорогих цепочек; полоскам/префетчу/пину невидим, т.к. их запросы kind-точные; живёт в общем видео-бюджете, invalidate_source сносит и его. Тест 65.

## Тесты
- Тест 8: eviction сжимает coverage ровно на выпавшие записи; quality не кросс-удовлетворяет.
- Тест 14 (совместно с kt-engine): pin головы loop-региона.
- Тест 37: no-read drops (`unused_evictions`) — выселение/перезапись записи ДО первого чтения; прочитанные записи (had_hit) в счётчик не попадают.

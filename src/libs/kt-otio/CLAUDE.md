# kt-otio

Родной формат проекта — OpenTimelineIO (.otio, JSON). Чистый Rust (serde_json),
БЕЗ FFmpeg/аудио/C++-биндингов/url-крейта. Зависимости: kt-time (+kt-model с
этапа convert). Эталон семантики — C++/Python библиотека OTIO 0.18.x.

## Инварианты

- **Идемпотентность записи** (тест 144): `write(parse(write(x))) == write(x)`
  байт-в-байт. Байт-passthrough ЧУЖОГО файла не обещаем — первое сохранение
  нормализует форматирование (так делает и эталон); неизменность гарантируется
  для содержимого, не для пробелов.
- **Passthrough, «не понимать наполовину»** (тесты 145-146): неизвестные ПОЛЯ
  известных схем — в `#[serde(flatten)] extra` на исходных местах; объекты
  неизвестных схем/версий-листьев — `RawObject` verbatim; чужие
  metadata-неймспейсы нетронуты, наш `"kt"` дописывается в конец. Версия
  ХРЕБТА (Timeline/Stack/Track) новее поддерживаемой → жёсткий отказ
  (позиции детей стали бы догадкой) — проверяется префлайтом по сырому Value:
  serde-мост превращает типизированные ошибки в `Json(custom)`, поэтому
  отказ хребта ДО `typed()`-парса, не внутри.
- **Канонический порядок ключей**: `OTIO_SCHEMA` первым, известные поля в
  порядке объявления структуры (заморожен тестами), `extra`/metadata — порядок
  документа. Требует `serde_json/preserve_order` — фича ГЛОБАЛЬНА для
  workspace (cargo unification): `serde_json::Map` везде становится IndexMap.
  Аудит на момент включения: Value жил только в тестах kt-model — безопасно;
  новые Value-потребители обязаны не полагаться на алфавитный порядок.
- **Время**: `RationalTime{value, rate}` — наши тики пишутся value=целое
  (двойная точность точна до 2^53), rate=90000.0; чужие rate квантуются
  `round(value*90000/rate)` — политика всей системы.
- `metadata.kt.v` — одна версия на ФАЙЛ (Timeline); новее нашей → явный отказ
  `KtMetaTooNew`. Вложенные kt-конверты версий не несут.
- Upgrade схем: только Clip.1→2 (media_reference → media_references), как в
  эталоне. Marker.1 и прочая архаика — passthrough-лист.
- `detect()` — по СОДЕРЖИМОМУ (OTIO_SCHEMA против format_version), расширению
  не верим. .ktproj как проект не открывается (Р.24 п.12) — только импорт.
- Пути (тест 147): target_url пишется относительным (POSIX-слэши), фолбэк —
  file://-URL с percent-encoding (как Resolve/Hiero); читаются относительный /
  абсолютный / file://; `synth:` — verbatim.

## Ограничения v1 (задокументированы, не реализуются)

SerializableCollection-корень → ошибка; .otioz/.otiod — нет; Retained-привязка
дорожек/переходов по индексам может переклеить чужие метаданные после
структурных правок (клипов не касается — ключ ClipId).

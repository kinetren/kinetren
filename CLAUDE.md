# Kinotrain

Нелинейный видеоредактор. Кодовая база — cargo workspace в **`src/`**.

Переписывание с C++/Qt (v1) завершено с полным паритетом; старый код удалён из рабочего дерева и доступен в git-теге **`cpp-reference-final`** (сверка поведения: `git show cpp-reference-final:<файл>`). `concepts/` — исторические заметки о проблемах v1 (русский; пути к файлам указывают в тег). `docs/porting-notes.md` — история порта и раундов, ЗАМОРОЖЕН на §470. **Актуальные контракты и причины решений — OpenSpec: `openspec/specs/<cap>/{spec,design}.md`**, обзорная карта — `docs/architecture.md`.

```bash
cd src

cargo test                 # conformance на реальных фикстурах включён по умолчанию
                           # (feature ffmpeg крейта kt-media; нужен бинарник ffmpeg
                           #  для генерации фикстур src/fixtures/gen.sh)
cargo clippy --all-targets
cargo run -p kt-app        # GUI
cargo run -p kt-cli -- …   # headless-рендер/экспорт
cargo run -p kt-cli -- probe <проект.otio> <от_с> <до_с> [--time]
                           # «что звучит в этом месте» (Р.43): эффективные события
                           # ПОСЛЕ морфер-слоёв, заказ префетча, чужое медиа в нём
                           # и стоимость сборки движка. Первое, что надо спросить
                           # по жалобе «тут звук/картинка от другого события».
                           # --time: успевает ли аудио-рендер в реальное время
                           # (о СКОРОСТИ судить только по РЕЛИЗНОЙ сборке — debug
                           # медленнее в 9 раз, п.301)
python3 scripts/subset-fonts.py  # сабсеты шрифтов CJK/арабского по каталогам перевода
./scripts/live-check.sh    # живые сценарии в виртуальном экране (Xvfb+openbox):
                           # настоящий kt-app, настоящие жесты, скриншоты в
                           # target/live-out; finish.sh зовёт их сам
./scripts/release-build.sh # релизный тарбол: dist-профиль (strip+LTO) в контейнере
                           # Ubuntu 22.04 → работает на glibc >= 2.35; внутри
                           # проверяются «ldd без libav*» и потолок GLIBC_
```

Системные требования для полной сборки (kt-media/kt-app): dev-пакеты FFmpeg (libavcodec/format/util/swscale/swresample), `clang` (bindgen), `libasound2-dev` (cpal/ALSA), бинарник `ffmpeg` в PATH (экспорт и генерация фикстур). Крейты kt-time/kt-model/kt-fx/kt-cache и ядро kt-engine собираются и тестируются **без** всего этого.

```
src/apps/kt-app     eframe GUI: таймлайн, превью, cpal-вывод, каталоги перевода i18n/
src/apps/kt-cli     headless-рендер (детерминизм, golden-тесты, CI)
src/libs/kt-time    тики 90 kHz, диапазоны, сетки fps/аудио-burst (без зависимостей)
src/libs/kt-model   модель таймлайна, команды, undo
src/libs/kt-otio    формат проекта OpenTimelineIO (.otio): схемы+passthrough, metadata["kt"]

src/libs/kt-text    растеризация титров: harfrust+ab_glyph, вендоренный Noto Sans (Р.52)
src/libs/kt-cache   кэш burst'ов + coverage (единственная правда о «прогретости»)
src/libs/kt-fx      AudioFx/VideoFx: slowedreverb, gain, видео-FX
src/libs/kt-engine  render graph, MediaWorker-планировщик, transport, prefetch, экспорт
```

В каждом libs/-крейте и в apps/kt-app есть свой `CLAUDE.md` с инвариантами и неочевидными решениями. Читай его перед правкой крейта.

Состояние UI-паритета со старым Qt-редактором (инвентаризация в docs/porting-notes.md): U1–U4 выполнены — маркеры/регион/loop/punch-out/копипаст-цепочки/volume rail/стерео-волноформы/филмстрип/метры+фейдер/медиа-бин/FX-редактор с автоматизацией/рендер-диалог/автосейв. E5 перенёс все 10 видео-FX, H1 — morpher-систему (morph-дорожки, размещение, FX-батчи, bake; тесты 35–36). I1 довёл перф-панель до уровня v1 и выше: 5-серийный график FFmpeg-активности (Total/Open/Read/VDec/ADec по живым счётчикам kt-ffmpeg::iostats), no-read drops (prefetch-thrash) в кэш-чёрне, занятость кэша от настоящего лимита, «pinned legends» с выносками, дедуп журнала «×N», пороговые предупреждения. Функциональный паритет с v1 ЗАКРЫТ (в v1 треть метрик панели были мёртвыми нулями — их не воспроизводим, см. тест 37).

## Модель времени

- Единица — **тик = 1/90000 c** (`kt_time::Tick`). 90 kHz делится на все частоты кадров (24/25/30/60) и на шаг аудио-burst.
- Аудио: **48 kHz stereo f32 interleaved** сразу после декода и до самого выхода. Аудио-burst = 1024 кадра = 1920 тиков ≈ 21.3 мс. Тик↔сэмпл: `samples = ticks * 48000 / 90000` — точно (15/8).
- Видео: кадр по сетке fps проекта; burst-индекс выравнивается на шаг `90000/fps`.
- В формате проекта — только тики, никаких миллисекунд.

## Инварианты (нарушение любого — регрессия; у каждого есть тест)

Полный текст каждого инварианта, его сценарии и обязательные тесты — в `openspec/specs/<cap>/spec.md`;
причины и история — в `design.md` рядом. Здесь — по строке, чтобы помнить.

1. **Аудио внутри движка всегда f32 48 kHz/2ch.** FX и микс не видят sample-rate файла — `audio-render`.
2. **FX-состояние трогает только аудио-render-поток.** Ни мьютексов вокруг FX, ни доступа из prefetch/метров; prefetch наполняет только пре-FX кэш — `audio-render`.
3. **Правка модели не уничтожает FX-состояние.** Diff цепочек по clip id: те же цепочки → те же state-объекты, параметры → `set_params`, буферы зануляются только при seek — `audio-render`.
4. **Кэш — единственная правда о coverage.** Полоски прогретости = `BurstCache::coverage()`; качество и ступень декода — часть ключа и часть ЗАКАЗА (префетч, композит, экспорт и полоски спрашивают одно и то же) — `video-plan`, `media-index`.
5. **Экземпляром декодера владеет ровно один поток.** **Живое воспроизведение** источниками не владеет: playback, префетч и тумбнейлы ходят через приоритетную очередь MediaWorker с generation-отменой, и playback не блокируется. **Офлайн-путь** открывает СВОЙ короткоживущий источник при трёх условиях: он им ни с кем **не делится**, **темпа не обещает** и его задача **конечна и отменяема**. Нарушение любого — обратно в очередь — `media-index`.
6. **cpal-колбэк — мастер-часы.** Playhead идёт по ВЫДАННЫМ колбэком кадрам; голодание даёт тишину, но не останавливает время (кроме первого кадра); в колбэке ни аллокаций, ни локов — `transport`.
7. **Код композиции один.** `frame_plan` общий для превью и экспорта; CPU — байт-эталон и полный фолбэк, GPU — по умолчанию и по допускам `FrameTol`; гео-серии сливаются одним проходом, план цепочки строит `plan_chain`; начатый экспорт не меняет бэкенд — `video-plan`, `video-fx`.
8. **Скролл/зум таймлайна не порождает декод-запросов.** Волноформы — из peak-пирамиды, тумбы — из sidecar, превью лент — из кэша по `content_hash` с дисковым ярусом — `media-index`, `compositions`.
9. **Экспорт полностью внутрипроцессный.** libavformat/libavcodec системного FFmpeg, каскад энкодеров с реальной проверкой открытия; ни временных файлов, ни внешнего бинаря — `export`.
10. **Бинарь не линкуется с libav*.** FFmpeg через dlopen, мажор по `avcodec_version()`, один бинарь на FFmpeg 6/7/8; `ldd … | grep -c libav` == 0 — `media-index`.
11. **Детерминизм.** Аудио — байт-в-байт всегда; видео на CPU — против закоммиченного эталона; на GPU — байт-в-байт между прогонами на одном устройстве, между машинами — в допусках от CPU; никакого wall-clock в офлайн-путях — `video-plan`, `export`.
12. **Показ видео не квантуется аудио-колбэком, UI не греет систему.** Позиция показа интерполируется (`video_playhead()`), repaint только при движении, ни аллокаций в draw-путях — `transport`, `ui-timeline`.

## Правила для агентов

- **Перед любой правкой UI/поведения — `docs/user-feedback.md`**: там история требований пользователя его словами (что просил, какие решения принял, что повторял). Предел, режим или вид, поставленные по его прямой просьбе, не меняются без новой просьбы. После каждого раунда замечаний список дописывается ТУДА ЖЕ, до начала работы.
- Перед правкой крейта — его `CLAUDE.md` и `openspec show <cap> --type spec` для capability, названных в его первой строке; `design.md` рядом — причины и отвергнутое. Перед архитектурными изменениями — `docs/architecture.md`. Работа ведётся как change OpenSpec (`/opsx:propose` → `/opsx:apply` → `/opsx:archive`); `openspec` требует Node ≥ 20 (`~/.nvm/versions/node/v24.21.0/bin`).
- **Перед реализацией новой ФУНКЦИИ (не дефекта) — `docs/features/`**: разведка чужих редакторов (что умеет Vegas/Premiere/Resolve/FCP/AE, за счёт какой неочевидной детали это работает, какой у нас вердикт). Нет заметки на фичу — сначала завести её, потом писать код; правила ведения — в `docs/features/README.md`, проверка — `python3 src/scripts/features-index.py --check`.
- Новый найденный дефект/тонкость → сразу документировать: сценарий с тестом — в `spec.md` capability, «почему» — в её `design.md` (или CLAUDE.md крейта, если это правило написания кода) и по возможности закрыть регрессионным тестом.
- **Старый файл перестал читаться — починка кладётся в ИМПОРТ, не в ридер** (решение
  владельца, Р.67): `File → Import older Kinotrain project…` → `kt-otio legacy_import.rs`,
  таблица починок с версией, для которой каждая заведена; снятие поддержки версии удаляет
  её починки. Ридер новых старых форм не учит; обычное «Открыть» отвергает файл с версией
  и именем пункта импорта. Спека — `project-format`.
- **Новый UI-сценарий (тест ≥ t783 в kt-app) несёт строку `- **ПУТЬ**`** — шаги мышью и
  что видит человек после каждого; сторож `src/scripts/specs-user-path.py --check` (t799)
  и `finish.sh`. Живой сценарий снимает скриншот на шаг (`kt_live.step`), `finish.sh`
  печатает их список после версии, отчёт о UI-работе их несёт. Прогон — на НАШИХ
  фикстурах, не на проектах владельца («п.1 но не на моих проектах», Р.67).
- **Коммитить каждый сложный этап АВТОМАТИЧЕСКИ** (требование владельца, 2026-09-22): раздел tasks.md / стадия раунда закончена и проверка зелёная → коммит сразу, без просьбы; сообщение по-русски, первой строкой — стадия и что сделано. Незакоммиченная работа в конце сессии — дефект процесса.
- `cargo test` обязан быть зелёным на каждый коммит; все тесты, названные в `TEST`-строках спек (сквозная нумерация tNNN), — регрессионные, их нельзя ослаблять/удалять без явного решения пользователя.
- Не добавлять зависимость от FFmpeg/аудио-железа в kt-time/kt-model/kt-fx/kt-cache/ядро kt-engine. GPU (wgpu) живёт ТОЛЬКО в kt-gpu; kt-engine знает лишь трейт `VideoGpuExec` (исполнитель инжектится из kt-app/kt-cli).
- **Dev-профиль собирается с `opt-level = 1`, зависимости — с 2** (п.301). `[profile.dev.package."*"]` покрывает ТОЛЬКО зависимости: свои крейты собирались без оптимизации, и на плотном монтаже аудио-рендер в dev уходил за 100 % реального времени (112 % против 10 % в релизе) — кольцо пустело, росли callback-underrun'ы. С уровнем 1 то же место занимает 18 %. Проверки переполнения и `debug_assert!` от уровня НЕ зависят и остаются включёнными. **О СКОРОСТИ всё равно судить по релизу**: замер — `cargo build --release -p kt-app` и `kt-cli probe … --time`.
- **Работа заканчивается `./scripts/finish.sh` и версией в отчёте** (требование п.7 р.12). `cargo test` собирает ОТДЕЛЬНЫЙ тест-бинарь и НЕ пересобирает `target/debug/kt-app` — тот, который запускает пользователь: дважды из-за этого он получал устаревшую программу и считал дефекты неисправленными. Скрипт пересобирает kt-app/kt-cli, печатает версию `vYY.MM.DD-hash` и чистит `target/dist-out` от старых тарболов; `--release` добавляет тарбол, `--deep` сносит регенерируемые `target/release` и `target/dist-container`.
- Версия программы — `kt-version` (build.rs, дата коммита + хэш). В манифестах остаётся `0.1.0`: semver не принимает `v26.08.27-…`. В debug-заголовке видна полная версия, в релизе — короткая `ktYY.MM`.

## Правишь крейт — какие тесты обязательны

Таблица «крейт → обязательные тесты» переехала в спеки: `openspec show <cap> --type spec`
даёт требования и сценарии capability, у каждого сценария — строка `TEST tNNN (путь)`.
Capability по поведению: time-model, transport, audio-render, video-plan, video-fx, audio-fx,
transitions, automation, morpher, compositions, generators, media-index, export,
project-format, durability, ui-timeline, ui-reach. У каждого `CLAUDE.md` крейта первой
строкой стоит, какие capability его накрывают. **Любая правка UI** — kt-app `reach_tests.rs`
(`ui-reach`) и `layout_tests.rs` (`ui-timeline`); любой текст в UI — `font_tests.rs`/`i18n_tests.rs`.

Всё вместе: `cd src && cargo test --workspace` (плюс `cargo clippy`).

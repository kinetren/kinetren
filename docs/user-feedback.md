# История требований пользователя

Первоисточник по тому, ЧТО просил владелец проекта и КАК он это формулировал.
`docs/porting-notes.md` отвечает на вопрос «какой дефект и каким тестом закрыт»,
`CLAUDE.md` крейтов — «как теперь писать код»; этот файл отвечает на вопрос
**«чего хотел пользователь и почему решение именно такое»**.

## Правила ведения (обязательно для агентов)

1. **Читать ПЕРЕД работой.** Прежде чем менять UI/поведение — проверь, не
   обсуждалось ли это место раньше. Если предел, режим или вид поставлены по
   прямой просьбе — менять их без новой просьбы нельзя.
2. **Дописывать СРАЗУ.** Новый раунд замечаний → сначала занести сюда список
   (своими словами пользователя, не пересказом), потом чинить. Ответы на
   уточняющие вопросы — тоже сюда, они и есть решения.
3. **Помечать повторы.** Если пункт повторяется — ставить ⚠ и число повторов:
   повтор означает, что правило не записано или записано слабо.
4. **Ссылаться на закрытие**: номер теста и/или пункт porting-notes.

## Раунды

### Р.4 — производительность и UX таймлайна (10 пунктов)
Лаги системы, дроп файла не под курсор, FX-пикер, скорость реверса, двойной
ползунок, порядок дорожек, отделяемое превью, дефекты свечения метров.
→ закрыто J1–J9, тесты 38–51.

### Р.5 — «система лагает» (6 пунктов) + диагностика
AMD-машина, дроп на Xorg, компактный контрол скорости, окно превью.
Ключевой диалог: «при плее fps=60, vfps=24» → нашлась причина: playhead
двигается квантами аудио-колбэка. Итог «да, стало супер быстро. нужно записать
изученные проблемы для других агентов» → уроки в apps/kt-app/CLAUDE.md, тесты
55–56.

### Р.6 — тема и таймлайн (пп.11–23)

ПЛОСКИЕ/СКУЧНЫЕ ИНТЕРФЕЙСЫ**»; титлбар — «совместить с тулбаром»; п.15 — «Space
дважды быстро»; скругления — «минимальные (1px)»; про подсказку — «я хочу чтобы

### Р.18 — продающий лендинг (не про редактор, про сайт)

«нужен "продающий" лендинг-сайт редактора, который раскажет потребителю что у
нас за продукт и что можно делать что и как, планы, и пр. я НЕ ИМЕЮ ВВИДУ
рассказывать то что там ffmpeg dlopen и прочие вещи, мне нужен лендинг для
пользователя, крутой, темный».

Решения пользователя по уточняющим вопросам:
1. «планы» = **роадмап** (что готово / что дальше), НЕ тарифы. Тарифного блока
   на сайте нет и не заводить без новой просьбы.
2. Язык лендинга — **английский** (интерфейс программы при этом русский).
3. Разместить: файл в репозитории (`site/index.html`) **и** опубликовать
   страницей по ссылке.
4. Показывать продукт **живыми скриншотами** приложения, не рисованным макетом.
5. Скриншоты — «делай как есть, чуть позже интерфейс переведем, выноски не
   делай»: русский UI на снимках оставлен как есть, английских выносок поверх
   картинок НЕТ, оговорки про язык интерфейса на странице тоже нет.
6. В роадмап вошло ровно то, что он выбрал: титры и переходы, цветокоррекция и
   LUT, фейды + автоматизация любых параметров FX, ещё аудио-FX, ещё форматы
   экспорта, упаковка deb/rpm/AppImage/Flatpak. **Wayland и локализацию UI в
   роадмап не ставить** — исключены им явно (язык «поправим сами»).

Сопутствующее наблюдение (дефект, не правился в этом раунде): подсказка клипа в
статус-баре обещает «двойной клик — FX», а `timeline.rs` по двойному клику
ставит регион на span link-группы; FX-редактор открывается только из ПКМ-меню
(«Эффекты…»).

### Р.19 — мультиязычность интерфейса

«надо ввести систему мультиязычности en/испанский/китайский/арабский/ru
программы».

**Это отменяет решение Р.18 п.6** («локализацию UI в роадмап не ставить, язык
поправим сами»). Новая просьба сильнее прежнего исключения.

Решения пользователя по уточняющим вопросам:
1. Арабский — **текст RTL, вёрстка LTR**: строки переупорядочиваются по UAX#9,
   панели/тулбар/таймлайн не зеркалятся (так же ведут себя Premiere и Resolve в
   арабской локали). Добавлено им: «если кода очень много — его надо делить на
   файлы».
2. Глифы китайского и арабского — **сабсет по каталогам переводов, скриптом,
   результат коммитится** (`scripts/subset-fonts.py`). Не вендорить шрифты
   целиком и не полагаться на системные.
3. Язык при первом запуске — **автоопределение по локали ОС**; выбор
   пользователя перекрывает автоопределение и сохраняется.
4. Объём — весь GUI **и** сообщения об ошибках, которые реально видит
   пользователь. И отдельно: «а если что-то остается на русском — то надо
   перевести на английский и далее все агенты по дефолту все строки пишут на
   английском».

**Сквозное правило, выведенное из п.4: исходный язык кодовой базы —
английский.** Любой новый строковый литерал (UI, лог, `#[error]`, вывод kt-cli)
пишется по-английски; русский текст интерфейса живёт только в `i18n/ru.toml`.
Комментарии и `docs/*.md` остаются русскими — это конвенция репозитория, речь
про строковые литералы. Закреплено тестом 131.

### Р.20 — лендинг: генератор, отдельные файлы, мультиланг (3 пункта)

1. «сделай чтобы лендинг генерировался из разных частей (т.е. чтобы из чего-то
   формализованного он генерировался в html)» → `site/build.py` + источники:
   `content/structure.toml` (форма страницы, картинки, аккорды клавиш, имена
   эффектов, числа) и `content/<lang>.toml` (только проза). Граница жёсткая:
   переводчику нечего сломать в вёрстке, правка вёрстки не трогает каталоги.
2. «не нравится что итоговый лендинг это один жирнющий html-blob» → `site/dist/`
   с отдельными CSS, шрифтами и картинками. Было 446 КБ одним файлом (89 % —
   base64, скриншот таймлайна вшит ДВАЖДЫ), стало 29–40 КБ на страницу при
   общих ассетах. Старый `site/index.html` удалён.
3. «введи мультиланг… язык можно по браузеру автоматом понять. нужно чтобы язык
   был в пути для SEO» → `/en/ /ru/ /es/ /zh-Hans/ /ar/`, коды те же, что в
   каталогах приложения. Корень `/` — диспетчер, повторяющий логику
   `i18n/detect.rs` (localStorage → navigator.languages → `zh-*` в упрощённый →
   английский); проверен на тех же случаях, что тест t130.

Решения пользователя по уточняющим вопросам:
4. Переводы: **сначала en + ru**; es/zh-Hans/ar пока заглушки с английским.
5. Непереведённые языки **генерировать, но с noindex** и не пускать в sitemap и
   hreflang. Сделано без ручных пометок: сборка считает долю значений, отличных

### Р.25 — кросс-рендер конформанс с чужим редактором

Задача его словами: «нужно теперь написать тест, который берет несколько otio
файлов из интернета, генерирует синтетические исходники, открывает otio через
чужой редактор (очень желательно headless) - рендерит, и еще рендерит в нашей
программе - в итоге надо сравнить отрендеренные файлы на наличие
пробелов/расхождений/и т.д.»

Решения раунда:

1. Чужой рендерер — **melt** (MLT 7.22, движок Kdenlive/Shotcut), полностью
   headless: «п.1. я поставил melt». Путь: python-адаптер `mlt_xml`
   (otio-mlt-adapter) конвертирует .otio → .mlt, дальше `melt … -consumer
   avformat:…`.
2. Сэмплы .otio из интернета — **закоммиченные копии** (fixtures/otio-samples
   + скрипт обновления с прибитым SHA): «из интернета» — про происхождение, а
   не про способ доставки; тест обязан работать офлайн и детерминированно.
3. Сравнение — **видео + длительность**; звук отложен (у mlt-адаптера аудио
   ограничено, а equal-power против линейного mix даёт заведомое расхождение).
4. Ярусы сравнения — **два**: строгое попиксельное сравнение для файлов из
   конструкций, которые рендерят оба; smoke (оба не упали + длительности
   совпали) для файлов с чужими конструкциями (вложенные Stack, эффекты
   Premiere).
5. Разведка настоящих сэмплов до написания теста нашла ДВА дефекта чтения
   чужих .otio (клип без `source_range` = весь available_range; клип с
   `media_reference: null` = неприлинкованный) — решение: **«Чинить в этом
   раунде»**, не обходить подготовительным скриптом.
6. Переход у края дорожки (fade-in/out) был ограничением v1 «дропаем с
   notice» — решение: **«Реализовать fade-in/out»** по-настоящему. Эталонная
   библиотека трактует такой переход как dissolve с Gap'ом, melt его рендерит,
   и молча терять чужой фейд нельзя.

### Р.29 — GPU-рендер видео и курс на AE-композитинг (архитектурный раунд)

Исходная формулировка (4 пункта):

1. «эффекты считаются на cpu??? у нас же egui, и это предпологает наличие
   gl-подобного интерфейса, разве нет?»
2. «надо подумать над системой эффектов в целом, чтобы по умолчанию всегда
   был gl/vk, и только если нет - пользователю об этом notice и работа на
   cpu (и то только для 2d)».
3. «Вообще - хотелось бы идти в сторону After Effects, т.е. у эффектов
   композитный движок должен быть. И эффекты по сути начинают
   категоризироваться на 2d версию и 3d версию (например, pan 2d, и pan 3d)».
4. «Не знаю как правильно выстраивается такая система, чтобы и 2d было и 3d
   в проекте».

Решения раунда (выбраны пользователем из предложенных вариантов):

1. **Детерминизм: «Float GPU + допуски».** Шейдеры f32; байт-в-байт
   сохраняется в пределах одной машины/драйвера; golden-тесты видео
   переезжают на допуски GPU-vs-CPU (CPU-путь остаётся байт-эталоном и
   фолбэком); публичное обещание лендинга «identical files, down to the
   byte» оговаривается («on the same machine»). Отвергнуты: fixed-point
   GPU с полным байт-в-байт; «GPU только превью, CPU экспорт».
2. **Глубина 3D: «Полный AE», этапами.** Дословно: «п.3. и не забывай что
   камер может быть несколько. может быть стоит взять что-то готовое».
   Оценка готовых движков проведена: берётся только glam (математика);
   bevy_render/three-d/rend3/vello/skia отклонены (другой мажор wgpu,
   GL-стек, maintenance mode, нерелевантно, бандл C++). На вопрос «камеру
   как текстуру использовать?» — render-to-texture у схемы по построению
   (все пассы пишут в offscreen-текстуры), «источник = вид камеры N» —
   этап precomp; настоящий 3D-движок при необходимости подключается как
   ИСТОЧНИК через трейт MediaSource, композитор на движок не меняется.
3. **Первый заход: «инфраструктура + порт 10 эффектов + первый 3D-эффект»**
   (Pan 3D: слой в перспективе + камера, сквозное доказательство
   модель→формат→рендер→экспорт).
4. Следствия, санкционированные этим раундом: Noise переводится на
   counter-based RNG (параллелизуемый; картинка шума меняется —
   перегенерация ТОЛЬКО noise-части golden'а t26); семантика таймлайна
   остаётся Vegas (порядок «сверху тот, кто позже», фейды, ручки);
   CPU-фолбэк не рисует 3D-эффекты (клип без эффекта + notice), экспорт
   3D-проекта без GPU — отказ с внятной ошибкой; роадмап сайта без
   отдельной просьбы не трогается. Полный план — обсуждение Р.29.

**Ответы пользователя на уточняющие вопросы (это и есть решения раунда):**

1. **Домен ключей автоматизации — «к материалу»** (вариант «как Premiere/AE и как
   уже сделано у Slowed»). Это ответ и на его вопрос «почему мы работаем в
   нормализованном времени»: домен «прогресс клипа 0..1» был выбран в Р.30 как
   самый простой для движка (одинаково с камерами), но семантику при обрезке
   никто не выбирал осознанно — она «резиновая», а `Split` вообще дублирует
   кривую целиком на обе половины. Теперь ключ стоит на своём кадре ИСТОЧНИКА:
   обрезка прячет/открывает ключи не искажая анимацию, Split делит кривую сам
   собой, reverse зеркалит сам собой, скорость учитывается сама. Два домена
   (видео-ParamCurve и SlowedKeyframe) сливаются в ОДИН. В UI показываются
   секунды + нормализованное вторым планом.
2. **Переходы: все три семейства, ~16 типов.** Вайпы (линейный ×4 направления,
   диагональ, iris, clock, шторки, luma), сдвиг (push, slide, cross-zoom, spin,
   whip-pan с motion blur), стилизованные (blur-dissolve, pixelate, glitch/VHS,
   film burn/flash, dip-to-color чёрный/белый/свой). Дефолт склейки остаётся
   Crossfade — новые типы выбираются явно.
3. **Аудио при переходе — кроссфейд с выбором кривой** (linear / equal-power
   (дефолт) / S-curve / exponential). Стилизованных аудио-переходов не делаем.
4. **Двойной клик по клипу открывает FX-окно** (подсказка статусбара это обещает
   с Р.18 и до сих пор врала); регион по событию — Shift+двойной клик и пункт
   меню.
5. **Рамка: Ctrl+drag всегда + toggle-кнопка «Selection tool»** (в режиме кнопки
   обычный драг по пустому рисует рамку). Ctrl+клик — добавить/убрать из
   выделения. Вводится множественное выделение событий (сейчас выделяется ровно
   одно), операции по множеству: перенос, удаление, копипаст, морферы, FX.
6. **Двойной клик по ленте метки-диапазона** ставит регион по её границам И
   выделяет события внутри; при пересечении нескольких — тот, по чьему
   флажку/имени кликнули.
7. **Порядок стадий: С6 → С1 → С2 → С3 → С4 → С5** (сначала быстрые видимые
   победы, потом фундамент).
8. **Placeholder отсутствующего видео — тёмная плашка с именем файла** и значком
   («сразу видно, ЧЕГО не хватает»); аудио — тишина. Уведомления: notice-список
   при открытии проекта, предупреждение в рендер-диалоге ДО старта, счётчики
   потерянного в сводке ПОСЛЕ.

Решено мной, не им (может поправить): шаблон имени рендера
`kt-<project>-<region>-<len>s.mp4`, где len — целые секунды диапазона; регион без
совпадающей именованной метки (или с пустым именем) — сегмент опускается; имена
санитизируются (пробелы→`-`, запрещённые ФС-символы→`_`).

**Деление на стадии** (каждая — свой заход со своими тестами):

- **С6** UX таймлайна и рендера: мультивыделение + рамка, двойные клики, шаблон
  имени файла, placeholder отсутствующих исходников (его пп. 7-10).
- **С1** фундамент: единый домен ключей, дескрипторы параметров (min/max/шаг/
  единицы/подпись — один источник правды), автоматизация ЛЮБЫХ параметров включая
  аудио, мастер-выключатель цепочки, копипаст-модель, формат v3 (его пп. 4, 6 и
  половина 2).
- **С2** единый виджет fx-chain (события/морферы/батчи), ревизия ВСЕХ полей
  ввода, окно всех цепочек события, поле источника с DnD и медиа-пикером (его п.2).
- **С3** единый виджет автоматизации: график ↔ таблица, мини-таймлайн двигает
  курсор основного, копипаст ключей (его п.5).
- **С4** переходы (его п.1). **С5** больше параметров у всех эффектов (его п.3).

**Известные дефекты, найденные разведкой этого раунда** (чинятся в своих стадиях,
записаны, чтобы не потерялись):

- `Split` копирует кривую автоматизации целиком в обе половины — анимация
  дублируется (С1, исчезает вместе со сменой домена).
- Кнопка «+ keyframe at playhead» у Slowed кладёт timeline-прогресс в
  source-домен: точка встаёт не под курсором при rate ≠ 1 (С1).
- График Slowed обрезан по оси rate на 2.0, а числовое поле пускает до 4.0 —
  точку выше мышью не поставить (С3).
- Одни и те же параметры имеют РАЗНЫЕ диапазоны в FX-окне, в окне морфера и в
  `param_specs()` (третий источник правды, его использует автоматизация) — С1/С2.
- Несолёные id (`Grid::new("vfx")`, `ComboBox "panmode"/"pan3dcam"`) сталкиваются
  при двойном вызове секции цепочки в окне морфера (С2).
- Подписи параметров FX — 37 сырых английских литералов мимо каталога i18n (С2).
- `set_fx_coalesced`/`set_fx_auto_coalesced`/SetFxBypass/SetTransition не бампают
  `model_rev` — фоновый автосейв может погасить звёздочку при незаписанных
  правках FX (С6, п. К1: это класс, а не одна функция).

Не делаем без новой просьбы: kt-cli по-прежнему игнорирует регион при экспорте
(расхождение с GUI); роадмап сайта не трогаем.

4. **Метод — параллельные агенты-исследователи** (партиями), а не
   последовательный сбор в основном диалоге.

**Что нашлось проверкой ещё до начала работы** (пользователь на это не жаловался,
но это меняет постановку): у Vegas Adjustment Event расходится с нашим морфером
не в одном месте, а в двух, и второе важнее первого.

- **Ползунок прозрачности** — у их события есть огибающая непрозрачности И фейды
  по краям, то есть эффект подмешивается ЧАСТИЧНО. У нас наложение бинарное:
  `MorpherEvent.enabled` вкл/выкл, в `MorphPatch` нет ни одного поля силы.
- **Что именно обрабатывается.** Vegas и AE применяют эффекты слоя к УЖЕ
  СМИКШИРОВАННОЙ картинке дорожек ниже. Мы же в `Project::effective_clips()`
  патчим КАЖДЫЙ клип по отдельности, и FX считаются пер-слой ДО композита. Из-за
  этого «прозрачность слоя» у нас негде реализовать, не тронув композит
  (инвариант №7 «код композиции один»), — и из-за этого же наш слой умеет то,
  чего не умеет ихний: подменять источник и точку входа у каждой цели.
- **Ограничение по дорожкам** — здесь разведка поправила меня самого: у Vegas
  НЕТ выбора дорожек. Единственный способ сузить «всё, что ниже» — сделать
  нужные дорожки compositing children дорожки-носителя, то есть перестроить
  структуру композиции проекта (и наоборот: перестройка компоновки молча меняет
  зону действия грейда). У нас это `MorphTargets::Areas` с полем `lanes` —
  декларативно и без перестройки проекта. Тут мы не догоняем, а опережаем.

Ответ на посылку «они там только для fx»: не только — у Adjustment Event есть
трим, сплит, копипаст, mute/lock, как у обычного события. Зато у нас есть то,
чего нет у них: подмена медиа и сдвиг `source_in` (морфер как «слой-подменыш»).

Каталог разведки — `docs/features/`, правила ведения — в его `README.md`,
решение «зачем он и почему ось по фичам» — п.245 `docs/porting-notes.md`.

**Что именно он поймал (разведка подтвердила три разных дефекта в п.1):**

- Ось кривой `rate` считается через варп, то есть ЗАВИСИТ ОТ САМОЙ КРИВОЙ:
  подвинул значение — точка уехала по экрану.

  материалу).
- Правая часть графика недостижима: ось размечена на `duration` материала, а
  доехать можно только до `duration · avg_rate`. Автоключ, который редактор

   ровно одну фразу решения Р.33 — «скорость учитывается сама».
2. **Экземпляр эффекта на КАЖДОМ событии пары A/V.** Одна добавка кладёт оба;
   `rate` и его кривая синхронны ВСЕГДА; реверб и режим кадров — свои;
   удаление одного убирает оба; разрыв link-группы прекращает синхронизацию.
3. **Параметр «Кадры», умолчание — «ближайший»** (держим кадр); «смешивание»
   (линейный бленд двух соседних) делается в этом же раунде отдельной стадией;
   fruc_vulkan — третьим режимом потом.
4. **`GOLDEN_AUDIO` перегенерировать РОВНО ОДИН РАЗ.** В golden-проекте теста 11

5. **Незакоммиченную работу Р.36** (каталог `docs/features/`) закоммитить

**Решено мной, не им (может поправить):**

- «Отдельная галочка» для видео — это ГАЛКА СЛОТА в полосе цепочки, а не новое
  поле: она уже есть, включена по умолчанию и рисуется зачёркиванием.
  Заводить второй выключатель того же смысла запрещает п.9 чек-листа.
- Правило п.1 применяется ко ВСЕМ параметрам цепочки, не только к `rate`:
  сейчас `mix`/`gain`/`pan` тоже индексируются по потреблённому материалу.

**Деление на стадии** (каждая — свой заход со своими тестами):

- **С1** домен автоматизации: карта варпа переворачивается в выходное время
  (`S = ∫rate` вместо ln/expm1), процессор сэмплирует по `tau`,
  «материал ↔ таймлайн» перестаёт зависеть от цепочки эффектов.
- **С2** видео замедляется, режим «ближайший»: одна точка правки
  (`clip_material_pos`), от неё сами следуют префетч, превью и экспорт.
- **С3** один эффект на пару A/V, синхронный `rate` (правило в модели).
- **С4** превью событий: волноформа и филмстрип по той же карте.
- **С5** режим кадров «смешивание».

**Известные дефекты, найденные разведкой этого раунда** (чинятся в своих
стадиях, записаны, чтобы не потерялись):

- `RATE_CLAMP` применяется НЕСОГЛАСОВАННО: `segments()` клампит концы и потом
  интерполирует, `eff_rate()` интерполирует и потом клампит. Расходятся, если
  ключ вне 0.25..32 — карта и DSP разъезжаются, а это промахи префетча и
  тишина. Руками из UI такой ключ не поставить, но `migrate_legacy_slowed`
  копирует значение без клампа (С1).
- Галка `ease` рисуется и для кривой `rate`, где она НИЧЕГО не делает —
  принудительно выключается в `from_curves` (С1).
- `warp_prefetch.rs` (t17) заполняет ЛЕГАСИ-поле `automation` при пустом
  `fx_auto`, а миграция в тестах не зовётся: кривой у него нет вовсе, и он
  недотестирует с Р.33.
- `integral_map.rs` не утверждает ничего — только печатает (С1).
- Домен аудио-автоматизации НЕ зеркалится при `reversed`, а UI зеркалит: у
  реверснутого аудио-клипа с кривыми они расходятся (дефект до этого раунда).
- Якорь зеркала реверса у аудио включает `WARP_SOURCE_MARGIN_FRAMES` (8192
  кадров ≈ 5 кадров видео) — реверснутая пара A/V разъедется на эти кадры,
  пока анкер не станет без-маржинальным (С2).
- `windows_on` уходит в ссылочные режимы РАНЬШЕ вето на варп: варпнутые клипы
  режутся морфер-слоем в режимах `Marks`/`Areas` (С2).
- `Split`/`TrimStart`/`punch_out_region` считают `source_in` линейно и на
  варпнутом клипе врут — уже сегодня, для аудио. Вне объёма раунда, записано.

Претензия 3 оказалась не набором отдельных бед, а одной причиной с четырьмя лицами:

* **Часы останавливаются на голодании кольца.** `varispeed_fill` при пустом кольце

* **«underruns давно сломался» — правда.** Промахи считались в РАЗНЫХ единицах:

* **«Левый/правый underruns» — это не каналы**, а «рендер/колбэк». В интерфейсе это не
  было подписано, и владелец читал их как L/R. Подписано.
* **«Звук от другого события» у реверса** — ось зеркала аудио включала запас

  материале. У события в `problems1` сдвиг составлял 63 % его длины.

счётчики: пока underrun'ы меряются в двух разных единицах и не подписаны, а отставания

### Диагноз (по коду, не догадка)

Каждый видео-FX — отдельная полная растеризация в буфер размера выхода с
квантованием в 8 бит между шагами; цепочка из жалобы — шесть растеризаций,
после второго grid детализации остаётся четверть, зум увеличивает её остатки.
Исходник ужат в разрешение выхода ещё декодером (`SWS_FAST_BILINEAR`).
Тесселяция не нужна и запрещена окружением (llvmpipe/downlevel: только
фрагментные пассы): все пять геометрических FX аналитически обратимы
(аффинные / тайл-modulo / гомография — pan3d кладёт плоский квад с
z_clip = 0), поэтому обратный per-pixel UV-маппинг во фрагментном шейдере
покрывает то же самое проще и точнее. Интуиция владельца «uv-маппинг исходя
из скейла» верна — только на пиксель, а не на вершину, и без тесселяции.

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **Конкатенация всегда, вопроса «когда включать» не существует.** Подряд
  идущие геометрические FX (Pan, CamMotion, Mirror, EventGrid, Pan3d)
  исполняются ОДНИМ проходом обратных отображений — как в Nuke/Fusion, в AE
  это collapse transformations. Серия длины 1 без минификации обязана остаться
  байт-в-байт сегодняшним одиночным проходом; серия длины k — один проход
  вместо k, то есть ДЕШЕВЛЕ пошагового. Нелокальные FX
  (Blur/Glow/Edges/VHS/Noise/Greenscreen) и LayerMix — барьеры, на них растр
  материализуется как раньше.
* **Pan3d считается и на CPU** (обратная гомография — «просто математика на
  пиксель»): решение Р.29 «3D только GPU» СНИМАЕТСЯ. CPU-путь снова полный
  байт-эталон, экспорт без GPU больше не отказывает (`GpuRequired` удаляется).
* **Суперсемплинг по якобиану при минификации ВЕЗДЕ** — включая одиночные grid

  внутренние ресемплы Blur/Glow (их размытость — суть эффекта), переходы
  (`transitions.rs`/`composite.wgsl`), `fit_into`, ужатие декодера в
  Quality.
* **Переключателей НЕТ вообще.** На вопрос «а имеет ли смысл переключатель
  делать? вкл/выкл? по умолчанию включенный.» после разбора выбран вариант без
  UI-тумблера И без диагностического env-флага: старое поведение — артефакт
  реализации, не стиль; второй путь — вечная поддержка.
* **Смягчения барьеров — потом.** На вопрос «а можно ли обойти нелокальные
  барьеры? ну вот тот же edges и vhs?» — точно нельзя нигде (в Nuke пиксельная

  гео-серии; (2) барьеры с учётом разрешения (edges/vhs/blur/glow в ×2–×4 при
  нетто-зуме хвоста, параметры ядер инвариантны к разрешению). Туда же —
  «декод крупнее Quality при нетто-увеличении >100 %» (единственный случай,
  где резкость потеряна ДО цепочки; трогает ключи кэша и префетч).
* На вопрос «если у нас есть gpu - то мы всегда на нем считаем же?» — да, при
  живом GPU всё видео на GPU (llvmpipe считается); CPU — эталон и фолбэк

  становится ПОЛНЫМ. На кадр CPU делает только построение программы —

## Раунд Р.45 (2026-09-13): «как с блокерами поступить» — смягчение барьеров

Сразу после проверки Р.44: «Проверил вроде работает. Давай теперь подумаем как
с блокерами поступить». «Блокеры» — барьеры конкатенации: нелокальные FX
(Blur/Glow/Edges/VHS/Noise/Greenscreen), рвущие гео-серии. Те же оговорки, что
в Р.43/Р.44: «Обратной совместимости не надо», «По любым пунктам могу быть не
прав, задавай вопросы где я не прав и по тонким моментам», «Делай заметки для
агентов».

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **Обе стадии смягчения в этот раунд, «декод крупнее Quality» — потом.**
  (а) Поточечные Greenscreen/Noise перестают рвать гео-серии: применяются к
  значению каждого сабтапа слитого прохода, в цепочечном порядке. Одиночный
  Greenscreen/Noise (вне серии) — прежний КОД ядра; байты гарантированы при
  K=1 его сегмента (при зумящем хвосте байты меняются по стадии (б) — это
  сознательно). (б) Нелокальные Blur/Glow/Edges/VHS исполняются в K×
  разрешении, K = нетто-зум хвоста цепочки, квант 1/32 и потолок 4 — как у
  тапов суперсемплинга.
* **Зерно Noise прибито к сетке СВОЕГО шага**: зум/поворот после него везут и
  масштабируют зерно вместе с картинкой (плёночное зерно материала), а не
  держат его экранным (оверлей-грейн). Ближе к духу старого поведения.
* **MAX_INTER_DIM = 4096** — потолок стороны K×-буферов, ПРОЕКТ-константа
  (не лимит устройства — иначе экспорт зависел бы от машины): превью — полный
  K=4, экспорт 1080p — до K=2, 4K — без K×. Поднять можно одной константой.

### Тонкие места, зафиксированные до работы

* K дополнительно ограничен «сжатием» выше по цепочке:
  K = квант(min(зум хвоста, стиснутая детализация до барьера)). Иначе
  `[vhs, zoom]` без сетки платил бы за K×-буфер, в котором деталей всё равно
  1× — их источник («декод крупнее Quality») отложен отдельным заходом.
* **«Хлопанье K»**: K зависит от автоматизации зума — на кадре пересечения
  порога 1 + 1/64 он скачет 1→2. Гистерезис запрещён детерминизмом; величина
  скачка ограничена допуском инвариантности вида (тест 303). Прецедент —
  квант тапов суперсемплинга (п.309, t300).
* Механизм «строить гео-программу в K·out» ОТВЕРГНУТ: ломает целочисленную
  геометрию сетки (10 px / 4 колонки при K=2 дают другую раскладку ячеек).
  Вместо него — конъюгация: программа всегда в 1×-семантике, масштабы вносят
  два аффина по краям (при K=1 — identity, байты Р.44 нетронуты).
* Голдены в этом раунде НЕ перегенерируются вообще: K=1-пути байт-в-байт.

→ реализация: пп.311–315 porting-notes, тесты t302–t306, стадии (1)(2)
вердикта F-CMP-001.

## Раунд Р.46 (2026-09-14): «давай делать» — декод крупнее Quality

Владелец сам вернулся к дважды отложенной стадии (3) вердикта F-CMP-001:
после объяснения смысла («Так, что там с декодом крупнее Quality? в чем
смысл?») — короткое «давай делать». Стоячие оговорки прежних раундов в силе:
обратной совместимости не надо, переключателей нет вообще, заметки для
агентов ведутся.

Суть: декодер ужимает кадр в Quality сразу (`sws_scale`, п.310а) — при
нетто-зуме цепочки >1 резкость потеряна ДО конкатенации. Лечение: заказывать
пре-FX кадр в S×Quality (S — целая «ступень» 1..4), когда цепочка
увеличивает и у файла есть запас натива.

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **Ступень S — по КЛИПУ**: максимум нетто-зума за всю длительность клипа
  (по кривым автоматизации и камерам). Один ключ кэша на клип: полоски
  прогретости точные, спаны декодера не рвутся, память предсказуема. Цена
  принята: клип, зумящий только в конце, декодируется крупно целиком
  (LRU-вытеснение ограничивает); правка кривой через порог ступени =
  перегрев клипа («хлопанье», прецедент кванта тапов п.309).
* **Дробный запас натива округляется ВВЕРХ**: натив 1920×1080 при Quality
  1280×720 и зуме ×2 → декод 2560×1440 — sws растянет 1920→2560 прямо при
  декоде, все 1.5× честных деталей файла доезжают до цепочки. Перерасход
  ограничен одной ступенью; правило простое — «любой запас файла работает».
* **Включается ВЕЗДЕ — превью и экспорт**, один путь кода (инвариант
  «превью == экспорт»). Само выключается, когда у файла нет запаса над
  Quality, и на нейтральных цепочках (нетто-зум ≤ 1 + 1/64).

### Тонкие места, зафиксированные до работы

* Размер декода — часть ЕДИНОГО источника правды `layers_at`/`wanted_frames`
  (урок t247d): префетч, превью и экспорт берут качество из заказа, никто не
  доклеивает его сам. Ступень детерминирована: S = f(проект, натив, Quality) —
  НИКАКОЙ зависимости от устройства или бюджетов (иначе экспорт зависел бы от
  машины). Декод никогда не мельче Quality (натив меньше Quality → S=1).
* Ведущие барьеры (до первого гео-рана) исполняются в S× ПРИНУДИТЕЛЬНО —
  физический кадр уже S×, benefit-формула Р.45 тут не голосует.
* Попутный фикс латентного дефекта Р.45: одиночный Mirror маршрутизировался
  в Legacy безусловно, а сборка плана ассертит 1×-края — цепочка
  `[сетка, vhs, Mirror, blur, зум]` валила debug_assert ещё до этой фичи.
  Правило: Mirror-Legacy только при k_in == k_out.
* Бюджеты чанка экспорта и лукахеда префетча считали размер кадра по
  Quality — при S>1 недооценка в S² раз (возврат «чёрного рендера» п.15 и
  кэш-чёрна) — чинятся в этом же раунде.
* sws/seek-чередование ступеней на одном файле (два клипа одного медиа с
  разными S) — принято: спаны амортизируют, цена замеряется в релизе.
* Голдены НЕ перегенерируются: в байт-эталонах нет нетто-зума, а натив
  синтетики меньше Quality — S≡1 на всех существующих путях.

→ реализация: пп.317–323 porting-notes, тесты t308–t318, стадия (3)
вердикта F-CMP-001.

## Раунд Р.48 (2026-09-14): «давай планировать этих кандидатов»

После Р.47 владелец спросил «что дальше?», получил три кандидата и

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **Pitch shift — ОБА движка**, «и п.1. и п.2. с глобальным
  переключением в проекте»: WSOLA (время-домен, дёшево, хорош на голосе)
  и фазовый вокодер (FFT, глаже на полифонии, размазывает транзиенты).
  Движок — настройка ПРОЕКТА, а не параметр эффекта: выбор один на весь
  монтаж, и переключение слышно сразу везде.
* **Автодакинг — в этот раунд, отдельной волной.** Закрывает F-AUD-002
  целиком вместе с лимитером («музыка забивает голос» — самая частая

* **Пресеты FX — глобально у пользователя** (+ несколько заводских):
  видны из любого проекта. Проект остаётся самодостаточным — вставленная
  цепочка живёт в .otio развёрнутой, пресет лишь шаблон вставки.
* **EQ — интерактивный график АЧХ**: кривая отклика и три точки-полосы,
  драг двигает частоту и усиление, колесо правит добротность; числовые
  поля остаются и синхронны с графиком.

### Тонкие места, зафиксированные до работы

* **Упреждение, а не задержка.** Эффект с look-ahead читает источник
  ВПЕРЁД выходной позиции, а выход остаётся выровнен со входом: для
  остального движка задержка нулевая, playhead и кроссфейды не едут.
  Цена — окно источника расширяется вперёд (одна функция обслуживает и
  рендер, и префетч, иначе вечный промах кэша).
* **«Греть» и «звучать» разводятся.** Сегодня это одно число
  (`chain_tail`): оно и прогревает seek, и продлевает конец события.
  Упреждение входит в прогрев, но НЕ продлевает событие — иначе клип
  начал бы звучать после собственного конца.
* **Смена окна упреждения пересобирает процессор** (структурная правка,
  как смена геометрии реверба): длина кольца — часть устройства узла, а
  не значение параметра. Слышно как мини-seek, документировано.
* **Нейтральный pitch shift обязан быть байт-в-байт прежним**: ноль
  полутонов и нет кривой — узел не трогает буфер (правило «умолчание
  нового параметра = прежнее поведение»). GOLDEN_AUDIO не трогается.
* **Дакинг — снимок, а не живой сайдчейн**: команда по явной просьбе
  считает огибающую дорожки-источника и кладёт кривую на Gain (один
  undo-шаг, не больше четырёх ключей на паузу). Сам по себе он потом не
  «отрастает»; поменялась музыка — вызвать снова. Живой сайдчейн (звук
  зависит от другой дорожки в реальном времени) — отдельная большая
  работа, вне раунда.
* **Пресеты — файл пользователя, а не модель**: сохранение и удаление
  пресета не попадают в undo проекта (undo правит монтаж, а не
  библиотеку); удаление предупреждает об этом подсказкой. Файл переживает
  незнакомые эффекты из будущих версий (они сохраняются как есть) и не
  перезаписывается более новой версией формата.
* Попутно закрывается хвост Р.38: вставка FX-цепочки в морфер молча
  теряла кривые. Вердикт разведки прямо запрещал заводить библиотеку
  пресетов раньше этого.

→ реализация: пп.337–348 porting-notes, тесты t322ж, t334–t350,
фич-заметки F-AUD-001/002/013 и F-AUT-004 (все закрыты).

  старте, если восстановленное новее проекта, программа спрашивает.
  Прежнее устройство оставляло пользователя без второго состояния на
  диске: откатиться было некуда, вчерашний файл был уже затёрт.
* **Пилоты офлайн-анализа — два**: интегрированная громкость (LUFS/dBTP)
  и синхронизация по волноформе. **Профиль шума — не сейчас**: он тянет
  за собой спектральное ядро, первый непрозрачный параметр модели и
  правку окна префетча, то есть сам по себе раунд.
* **Вложенность (решение на вперёд, для Р.50)**: вложенная секвенция —
  **ссылка на объект ВНУТРИ проекта** (путь Premiere/FCP), и она
  **наследует настройки родителя**. Своих fps и размера у неё нет —
  значит нет и пересчёта сеток, «мыла» и рывков.

### Тонкие места, зафиксированные до работы

* **Автосейв перестаёт гасить звёздочку.** Сегодня он её гасит, и это
  закреплено тестом; в правилах проекта при этом записано обратное. После
  раунда код совпадёт с правилом, а t194/t200 переписываются — это прямая
  санкция владельца, а не ослабление тестов замороженного диапазона.
* **Программа начинает спрашивать перед выходом и сменой проекта.** Право
  не спрашивать было законным ровно потому, что автосейв писал поверх
  файла пользователя — терять было нечего. Владелец это убрал, значит
  снято и право молчать.
* **Замок ставится на ФАЙЛ ПРОЕКТА, а не на программу.** Запрет второй
  копии сломал бы живые сценарии (они запускают программу параллельно) и
  сам сценарий «открыл второй раз, чтобы посмотреть другой кусок».
  Вторая копия работает, но честно предупреждает и пишет своё
  восстановление.
* **Строгость к битым файлам.** Клип с испорченной нашей секцией
  метаданных перестаёт молча терять связь A/V, громкость и прозрачность:
  загрузка отказывает и называет адрес каждого битого клипа. Цена: файл,
  испорченный ПРЕЖНИМ дефектом, теперь не откроется — но он и сейчас
  открывается неправильно, просто молча.
* **Ширина панели метров уезжает из файла проекта** в пользовательское
  хранилище: сегодня, открыв чужой проект, вы теряете свою настройку, а
  сохранив — навязываете свою чужому.
* **Демо-проект начинает работать без медиафайлов** (синтетические
  источники по умолчанию): восемь путей, на которые он ссылается, не
  существуют в поставке вовсе.

### Что вышло по итогу Р.49 (дописано после работы)

* **Программа больше не теряет работу.** Фоновая запись идёт в свой файл
  восстановления, проект меняет только Ctrl+S; при старте несохранённое
  предлагается вернуть — с путём и временем; выход и смена проекта
  спрашивают; убитая программа оставляет работу на диске, и это проверено
  настоящим SIGKILL в живом сценарии.
* **Правая кнопка перестала молчать** в двенадцати местах, а две подсказки,
  которые годами обещали несуществующее поведение, стали правдой: двойной
  клик по линии уровня сбрасывает её, а аккорд «Del» больше не обещается
  там, где он ничего не делает.
* **Программа научилась слушать материал**: громкость по стандарту
  вещания (LUFS/dBTP/LRA) у каждого исходника и у готового экспорта,
  синхронизация двух записей по звуку одним пунктом меню. Оба счёта идут
  на проходе, который и так был нужен, — новых ожиданий у монтажёра не
  появилось.
* **Автодакинг уехал в фон**: раньше окно замирало на десятки секунд.

Чего сознательно НЕ сделали и почему: кнопки «нормализовать до −23» нет —
цель нормализации выбирает человек (вещание −23, стриминг −14, кино −27), а
применять её к уже записанному файлу значит перекодировать его ещё раз;
синхронизация не связывает события в пару — это отдельное решение монтажёра;
правая кнопка по ключу кривой не удаляет его сразу — иначе обещание «правой
кнопкой можно пробовать безопасно» перестаёт быть правдой везде.

## Раунд Р.50 (2026-09-15): «давай дальше» — вложенные секвенции

Владелец сказал «давай дальше»; следующим по его же разбивке шли вложенные
секвенции, вынесенные из Р.49 отдельным раундом. Два решения, определявшие
половину кода, были приняты ещё тогда и повторены здесь без изменений;
ещё два потребовались перед началом работы.

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **Вложение — ссылка на объект ВНУТРИ проекта** (путь Premiere и FCP), а
  не на файл на диске: один суб-таймлайн стоит в нескольких местах, правка
  внутри меняет все сразу. *(принято в Р.49, на вперёд)*
* **Вложение НАСЛЕДУЕТ настройки родителя.** Своих fps, растра и частоты у
  него нет — значит нет ни пересчёта сеток, ни «мыла», ни рывков, которыми
  славится нест у всех пяти конкурентов. Мы сознательно отличаемся от них
  всех. *(принято в Р.49, на вперёд)*
* **Чужие вложенные `Stack` читаются как настоящие секвенции УЖЕ в этом
  раунде.** Закрывается дыра совместимости, зафиксированная в п.158: мы
  честно читаем чужие вложенные композиции и честно рисуем на их месте
  пустоту, поэтому сэмпл `nested_example` навсегда сидел в smoke-ярусе
  кросс-рендера. Цена принята владельцем явно: импорт чужих файлов
  начинает давать ДРУГУЮ модель, чем сегодня.
* **Внутрь вложения можно класть ВСЁ**, включая морфер-слои и камеры.
  Альтернатива («только события и переходы, свернуть под морфером —
  честный отказ») отвергнута: она примерно вдвое короче, но оставляет
  пользователю класс «это свернуть нельзя».

### Тонкие места, зафиксированные до работы

* **Вложение с пустой цепочкой ТОЖДЕСТВЕННО своему содержимому** — прямое
  следствие наследования настроек. Поэтому раскрытие внутрь `effective_clips`
  (туда же, где раскрывается морфер) даёт картинку и звук раньше, чем
  появится настоящее поддерево плана, и служит ЭТАЛОНОМ-ОРАКУЛОМ для него:
  готовое поддерево сверяется с раскрытием байт-в-байт.
* **Найден дефект, которого ещё нет.** Аккумулятор композита хранит
  премультиплицированный цвет при прямой альфе, а наложение слоя ждёт
  прямой. Подать собранный кадр вложения обратно в композит — картинка
  вдвое темнее РОВНО в полупрозрачных местах, что легко списать на «так и
  задумано». Лечится одной конверсией на границе вложения, и на неё
  обязателен red-proof.
* **Номер события становится уникальным во ВСЁМ документе**, а не внутри
  ленты: конверты материала и переходов хранятся глобальными картами по
  этому номеру, и совпавшие номера из разных лент молча обменялись бы
  ссылками на материал и стартовым таймкодом.
* **Предел глубины вложенности — 4**, и это посчитанное число, а не
  круглое: на каждый уровень в памяти видеокарты живут два аккумулятора и
  результат, около 25 МиБ при 1080p, при бюджете 128 МиБ.

### Что вышло в волне А (пп.378-383)

Свернуть, сохранить, открыть, отрендерить, развернуть — работает от края до
края. Правка внутри пока идёт через «развернул, поправил, свернул»: вход
внутрь — волна В. Цепочка, реверс и варп на самом вложении до волны Б
ОТВЕРГАЮТСЯ с объяснением, а не считаются неправильно: снаружи они должны
применяться к собранной картинке, а раскрытие применило бы их к каждому
куску — это другой результат, и молча выдавать его нельзя (правило 16).

Дыра совместимости п.158 закрыта: чужие вложенные `Stack` и `Track` внутри
`Track` читаются настоящими лентами. Цена, о которой было сказано заранее,
заплачена — импорт чужих файлов теперь даёт другую модель, чем давал.

### Чем Р.50 закончился

**Вложение работает от края до края.** Свернуть кусок монтажа, войти двойным
кликом, поправить, выйти, сохранить, открыть — и всё это с ОДНОЙ лентой,
поставленной в нескольких местах: правка внутри меняет их все, а бейдж «×N» на
событии говорит, сколько мест изменится вместе, и ведёт к ним по кругу.

Главное — не удобство группировки, а ГРАНИЦА ПОРЯДКА ОБРАБОТКИ: цепочка,
навешенная на вложение, применяется к СОБРАННОЙ картинке и к общему миксу, а
не к каждому куску. Ровно этого нельзя было выразить никак иначе.

Дыра совместимости п.158 закрыта: чужие вложенные `Stack` читаются настоящими
лентами. Строгим ярусом кросс-рендера сэмпл всё равно не стал — но по
противоположной причине: строгий прогон показал, что вложенные `Stack`
выбрасывает ЭТАЛОН, и расходимся не мы.

Живой сценарий нашёл дефект, которого не видел ни один тест: вставка копии
рядом с вложением МОЛЧА не происходила (счётчик свежих адресов не видел
событий внутри лент). Это ровно тот класс, ради которого живые сценарии и
заведены.

## Раунд Р.51 (2026-09-16): переходы — «симбиоз двух событий»

Претензия дословно (первая из списка, который владелец попросил «поделить
на стадии, обсудить и решить»):

> не хватает эффектов переходов - почему то ты все эффекты базируешь только
> как наложение A на B, где у B есть "эффект", а переходов с симбиозом двух
> событий у тебя нет, нет инверсий перехода и т.д.

И отдельно: «Обратной совместимости не надо. По любым пунктам могу быть не
прав, задавай вопросы где я не прав и по тонким моментам.»

### Что показала разведка до вопросов

Претензия к архитектуре не подтвердилась: пара перехода схлопывается в один
слой (`PlanLayer::Dissolve`), ядро видит оба кадра, 7 видов из 16 двигают
оба. Но подтвердилась по впечатлению: **Push и Whip сломаны** — въезжающий
кадр сэмплится со смещением −dir вместо +dir, координата клампится к кромке,
и вместо кадра B въезжает его размазанная первая строка/колонка. Именно так
выглядит «у одного из кадров какой-то эффект». Тесты слепы: t225 гонял
сплошные цвета (любая координата даёт тот же цвет), t224 сверяет CPU с GPU —
а зеркала сломаны одинаково. Второй найденный дефект того же духа: повторный
драг уголка-фейда и повторный наезд Move-драгом молча сбрасывают выбранный
вид перехода в кроссфейд и стирают его кривые (против правила 20 «ничего не
отрубается само»).

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **«Симбиоз двух событий»** = (а) переходы, где движутся ОБА кадра, и
  (б) **переход должен работать на наложении** (перекрытии клипов одной
  дорожки), а не только на стыке встык. Галерею с живыми мини-превью и
  связь вида видео-перехода со звуком НЕ выбрал (решение Р.33 «звук всегда
  кроссфейдится» остаётся).
* **Инверсия перехода — галка у видов** («поменять местами роли сторон»),
  НЕ кривая прогресса как в Vegas и НЕ ease-пресеты — оба варианта
  предлагались и выбраны не были.
* **Новые виды — все четыре семейства**: 3D (page peel/roll, куб,
  переворот/двери), паттерн-маски (жалюзи, шахматы, случайные блоки,
  спираль), split/squeeze/stretch/swap, и параметры к имеющимся
  (произвольный центр iris/zoom/spin и т.п.).
* **Состав — «современный микс»**: классика Vegas плюс модные из
  Premiere/Resolve/CapCut (shake, film burn, light leaks, zoom-blur);
  строгое копирование набора Vegas предлагалось и выбрано не было.
* **Обратной совместимости не надо**: якорь «ровно 16 видов» (t223) снят
  его новым решением, поведение существующих видов можно менять (починка
  push/whip меняет картинку старых проектов), формат бампается, старые
  сборки на новом файле получают честный отказ.


### Чем Р.51 закончился

**Оба слова претензии стали кодом.** «Симбиоз»: Push/Whip починены
(въезжает настоящий кадр, а не размазанная кромка — дефект жил четыре
раунда, потому что оба стража были слепы каждый по-своему), добавлены
сдвиги, где движутся оба кадра (split/squeeze/stretch/swap), и переходы
заработали НА НАЛОЖЕНИИ: окно = сама зона перекрытия, ручек у него нет
(окно следует за тримом клипов — урок Kdenlive из F-TL-010 снят
конструкцией), кривая аудио на наложении начала работать, зона голого
наложения помечена штриховкой. «Инверсия»: галка на событии перехода,
исполняется планом одной подстановкой `kernel(b, a, 1−k)` — ядра, зеркала
и кэш-ключи не тронуты; у симметричных видов галка честно спрятана.

Видов стало 33 (узоры, сдвиги, стилизованные, объёмные), у
iris/clock/zoom/spin появился произвольный центр (анимируемый). Объёмные
(flip/cube/door/peel/roll) заехали БЕЗ единого нового прохода — в
свободные 16 float униформы композита, гомографии считает f64-код, общий
для обоих бэкендов. Попутно закрыт дефект Р.50: переход внутри вложенной
ленты молча не кроссфейдил звук.

Сознательно НЕ сделано: кривая прогресса и ease-пресеты (владелец выбрал
галку — предлагались явно), галерея с мини-превью и связь вида со звуком
(не выбраны), ступень декода для zoom-in переходов (известное
ограничение, п.400 — отдельный раунд, если понадобится резкость).

## Раунд Р.52 (2026-09-16): видео-генераторы — «как минимум текста разного»

Претензия дословно (первая из списка, который владелец попросил «поделить
на стадии, обсудить и решить»; вопросы задавались 2026-09-14, реализация
стартовала после Р.47–Р.51):

> не хватает видео-генераторов, как минимум текста разного, и т.д. и т.п.
> как в серьезных программах

И отдельно: «Обратной совместимости не надо. По любым пунктам могу быть не
прав, задавай вопросы где я не прав и по тонким моментам. Делай заметки
для агентов.»

### Что показала разведка до вопросов

Прямых просьб про генераторы в истории не было — но титры владелец выбрал
в роадмап ещё в Р.18 («титры и переходы, цветокоррекция и LUT…»), и
переходы из той же строки уже сделаны (Р.33, Р.51). Заметки фич уже
существовали с вердиктами «берём, делать вместе»: F-TXT-001 (текст в
кадре, приоритет A) и F-TXT-003 (генераторы) — обе независимо пришли к
«генератор/титр = третий вид источника без файла (`MediaSource`), схема в
пути медиа + единая фабрика». Разбор псевдо-пути `synth:` к этому моменту
продублирован в трёх файлах и однажды уже расходился по регистру (сноска
п.211) — фабрика нужна была и без генераторов.

### Решения владельца (ответы на прямые вопросы, AskUserQuestion)

* **Порядок**: фундамент (фабрика) + сплошной цвет → статичный текст →
  остальные генераторы (градиент/шахматка/шум/SMPTE/таймкод) → анимации.
  Варианты «текст в первую очередь» и «сначала все простые» предлагались
  и выбраны не были.
* **Текстовый движок — шейпер сразу**: harfrust (позиционирование:
  кернинг GPOS, лигатуры, вязь) + ab_glyph-растеризатор пикселей. Вариант
  «просто ab_glyph, шейпинг потом» предлагался и выбран не был (у Noto
  Sans legacy-таблицы `kern` нет вовсе — без шейпера титры остались бы
  без кернинга).
* **Шрифты — вшитые + системные сразу**: вендоренные начертания как
  эталон детерминизма (голдены только на них) + выпадающий список
  системных; проект на машине без шрифта — подмена вендоренным + видимое
  уведомление. Вариант «сначала только вшитые» выбран не был.
* **«Обратной совместимости не надо»** уточнено (multi-select): (а)
  старым сборкам новые проекты не обязаны — генератор у них деградирует
  в заметную заглушку, конвертеров не заводим; (б) легаси-импорт титры/
  генераторы старых форматов не конвертирует. Вариант «можно ломать и
  чтение старых проектов» НЕ выбран — байт-стабильность нетронутых
  старых файлов остаётся.

### Чем Р.52 закончился

**«Как минимум текста разного» — сделано, и не только текст.** Восемь

Плюс два разрешения, снявших половину церемонии: «Обратной совместимости
не надо» и «По любым пунктам могу быть не прав, задавай вопросы где я не
прав и по тонким моментам».

### Что разведка возразила владельцу (и он согласился)

* **Персист миниатюр в индекс-БД не нужен.** Дорогая половина превью —
  ДЕКОД — уже персистится: тумбы источников 320×180 лежат JPEG'ом в
  `thumbnails` sidecar-БД с Р.7. Наложить цепочку на готовый кадр стоит
  доли миллисекунды (видео-FX — чистые функции без состояния, замеры
  п.198), то есть ДЕШЕВЛЕ, чем прочитать результат из sqlite. Вместе с
  персистом отпала и фоновая джоба «рендерить после добавления сурса»:
  прогревать нечего, кроме обычной постер-тумбы, которая и так греется.
* **Секундный гард нужен не рендеру, а ЗАКАЗАМ декода.** Рендер из уже
  готовых тумб можно показывать сразу; выжидать имеет смысл только перед
  тем, как просить воркер декодировать недостающий кадр (FFmpeg
  open/seek) — иначе мисклик стоит настоящего декода.
* **«Полоска под каждый пресет» требовала уточнения постановки**: с Р.48
  пресет — это БЛОК ЦЕПОЧКИ в библиотеке вне проекта, он не принадлежит
  эффекту, и «полоска пресетов напротив эффекта» на этой модели не
  выражается.

### Решения владельца (AskUserQuestion)

* **Раскладка — полоска миниатюр в КАЖДОЙ строке эффекта** (галерея со
  скроллом), имя под миниатюрой мелким кеглем, усечение плюс полное имя
  по наведению. Варианты «две панели как в Vegas» и «гибрид с
  разворотом» предлагались и выбраны не были.
* **Иконка — глиф категории ПЛЮС генерённая миниатюра**: эффект
  накладывается на встроенный тест-паттерн. Вариант «только глифы
  Phosphor» отвергнут (на 27 видов подходящих глифов не найти, и уже
  были случаи tofu), вариант «только картинка» — тоже.
* **В индекс-БД не пишем** (см. возражение выше), RAM-LRU на сессию.
* **Кадр полоски — WYSIWYG**: уже стоящая цепочка клипа ПЛЮС кандидат в
  конец, на ближайшей тумбе к позиции курсора. Вариант «чистый кадр плюс
  один эффект» отвергнут: после клика получилось бы не то, что показано.
* **Полоска эффекта = шаблон + встроенные ВАРИАНТЫ + свои одноэффектные
  пресеты этого вида.** Варианты — наши заводские наборы параметров с
  именами в каталоге (клик добавляет эффект сразу настроенным);
  библиотека Р.48 при этом не трогается.
* **Секция пресетов-библиотеки тоже получает миниатюры** — включая
  многоэффектные блоки; аудио-пресеты и аудио-пикер остаются текстовыми
  (миниатюра звука бессмысленна).

### Что нашлось по ходу (и чего в претензии не было)

* У меню egui дефолт `CloseOnClick`: попап закрывается ЛЮБЫМ кликом
  внутри. Галерея с кликабельными миниатюрами была бы мертворождённой —
  нужен `CloseOnClickOutside`.
* Ячейки НИЖЕ СГИБА прокрутки считались и публиковали свои
  прямоугольники: 160 миниатюр на одно открытие при полутора десятках
  видимых, а живой сценарий кликал по невидимой ячейке мимо попапа — в
  таймлайн.
* Подписи вариантов общие на весь реестр («Мягко» есть у шести видов),
  поэтому доступное имя ячейки пришлось сделать составным.
* Филмстрип и волноформа РЕВЕРСИВНОГО события без варпа показывали не то,

* У f32-параметра ровный потолок спеки после `set_param` оказывается ВНЕ

### Где владелец был не прав (и это важнее, чем где прав)

* **Пп.1 и 4 — не «не срабатывает», а ПРЯМОЙ ЗАПРЕТ.** `validate_reel`

  (`NestInstanceNotChainable`, Р.50 п.382). Шаблон кнопки пикера —
  `slowed_reverb(0.82, …)`, то есть `rate != 1` сразу, и команда падает с
  английским техническим текстом в статусбаре. Запрет стоял честно:
  механизма (суб-микс, читаемый не по порядку) не было.
* **П.3 — генераторы НЕ теряются.** Они живут в общем `project.media`, и
  клип уезжает внутрь вместе со ссылкой. Теряются `lane_order` и камеры, а
  морфер уезжает и там умирает: без `lane_order` порядок строк дефолтный, в

  слоя — под ним не оказывается ничего.
* **П.6 — курсор как раз переводится**, не переводится ВИД: прокрутка
  оставалась в оси корня. Дефект не видел ни один тест, потому что во всех

  тождество — та же дыра, что t456.

### Решения владельца (AskUserQuestion)

* **Хвосты за обрезкой при раскрытии — затемнённо, ПРАВИТЬ МОЖНО, край
  экземпляра тянуть прямо там.** Варианты «только чтение» и «не показывать»
  предлагались и выбраны не были.
* **Лента в N местах: правка правит ВСЕ места**, ссылочная семантика
  сохраняется; при первой правке — предупреждение с глаголом «Отвязать эту
  копию». Варианты «спрашивать каждый раз» и «всегда отвязывать» отвергнуты:
  правка всех мест — это то, ради чего ленту и заводят.
* **В полном режиме входа играет САМА ЛЕНТА с t=0.**
* **Морфер: не резать ради цепочки — гасить силу вне окна.** Вариант
  «резать, но только сужая» и вариант «оставить как есть, но назвать»
  выбраны не были. Формулировка вопроса потребовала второго захода: на
  первый владелец ответил «я не понимаю проблему, почему морфер не
  накладывается четко по границам, а херачит на все событие если есть
  невинный переход у события» — и был прав, потому что резка ради цепочки
  не нужна вовсе.
* **Лента становится объектом бина** (карточка, ×N, полный набор глаголов).
* **Из попутно найденного в раунд берётся только потеря работы на дропе
  `.otio`.** Остальное (undo запирает внутри ленты; два экземпляра делят
  реверб; морф-слой обходит запрет на варп) документируется и откладывается.

### Что нашлось по ходу (и чего в претензии не было)

* **Дроп `.otio` делает `*self = app` без `guard_unsaved` и без
  `claim_project`** — в обход всего, что построено в Р.49. Несохранённая
  работа исчезает без единого вопроса, и замок на файле не берётся.
* **Бин не показывает ленты вовсе.** Поставить композицию во второе место
  можно только копипастом уже стоящего экземпляра; завести пустую ленту или
  удалить конкретную — нечем.
* **Реверс-транспорт над вложением — тишина.** `render_frames_raw` не
  оборачивает фетчер, заказ префетча внутрь уходит, а чтение до него не
  доходит: нарушение «заказ == чтение» прямо сейчас.
* **Адрес ленты в видео-плане идёт без `NEST_TAG`** и численно совпадает с
  адресом ФАЙЛА с тем же id — ровно то, что `validate` запрещает.
* **Дисциплина вложенности не спустилась в крейтовые `CLAUDE.md`**, а
  `docs/architecture.md` про вложенность не знает вовсе (последняя правка —
  до Р.50).

## Раунд Р.57 (2026-09-19): скорость со знаком — реверс внутри slowed и точная скорость транспорта

Две претензии владельца, дословно:

> 1. реверсивное проигрывание в slowed-эффекте (отрицательный rate)
> 2. в slowed да и в timeline rate-контроллер должен давать выставить значения
>    не превращая диапазон -0.25...0...0.25 в 0 т.е. я должен иметь
>    возможность выставить 0,05 или -0,03 например.

Плюс прежние разрешения: «Обратной совместимости не надо», «По любым пунктам
могу быть не прав, задавай вопросы», «Делай важные заметки для агентов, тесты».

### Где владелец был прав (везде) и что за этим стояло

* **Транспорт.** Предел 0.25 живёт ТОЛЬКО в маппинге ползунка: мёртвая зона
  7 % хода отдаёт ровно 0, а её край сразу равен 0.25× — интервал (0, 0.25)
  непредставим по построению. Решения владельца за этим нет: число совпало с
  клампом варпа, и совпадение приняли за правило. Поле ввода убрали в Р.7 по
  его же просьбе («две параллельные полосы, высоту не менять») — форма
  сохраняется, поле возвращается НА МЕСТО полосы, а не окном.
* **Slowed.** Малое или отрицательное значение молча превращалось в 0.25×
  тремя независимыми клампами (карта варпа, процессор, поле). Отрицательной
  скорости не было как понятия: карта обратима только при строго растущем
  потреблении, аудио-варп читает источник строго вперёд, реверс — статическое
  зеркало на весь клип, префетч и суб-микс лент берут окно по двум концам.
  Заметка F-SPD-002 называла это «отдельным раундом с честной ценой» — он и
  настал.

### Решения владельца (AskUserQuestion)

* **Минус в slowed — как velocity-огибающая Vegas:** позиция в материале =
  точка входа + ∫скорость; минус идёт НАЗАД по материалу внутри события,
  направление может меняться посреди события, 0 — стоп-кадр, у края
  материала — держим кадр. Флаг «Реверс» остаётся зеркалом поверх. Вариант
  «минус = второй вход в кнопку Реверс» отвергнут.
* **Звук тянется до |rate| = 0.01, тишина только в нуле** (хвост реверба
  дозвучивает). Вариант «ниже 0.25 глушить» отвергнут.
* **Транспорт: плавная шкала ±0.01…±2 + Shift + ввод числом** (правый клик
  или Ctrl+клик по полосе); стоп — узкая зона 1–2 px в центре; двойной клик
  — 1×; высота виджета не меняется.
* **Диапазон slowed −32…+32, ноль разрешён**; графику автоматизации —
  нулевая линия и лог-шкала по модулю.

### Следствие, которое надо знать

Постоянная −1 с начала события идёт в материал ДО точки входа (это и есть
семантика Vegas). Она равна флагу «Реверс» при +1 только если точку входа
сдвинуть на длину события. Это определение, а не дефект.

* **Зону до нуля внутри открытой ленты показывать с вуалью**, как хвосты

  заходят. Вариант «не показывать» отвергнут.
* **Дисковый кэш превью лент — в готовом файле индекса**

* **Разрастание OTIO отложить.** Попутная находка: каждый экземпляр ленты

Плюс прежние разрешения: «Обратной совместимости не надо», «По любым пунктам
могу быть не прав, задавай вопросы где я не прав и по тонким моментам, не
ограничивайся в вопросах», «Делай важные заметки для агентов, тесты и т.д.».

### Где владелец прав (везде) и что за этим стояло

* **П.1.** Параметризовать композицию сегодня нечем: у ленты нет ни одного
  собственного поля-параметра, а экземпляр отличается от соседа только своей
  цепочкой эффектов, уровнем и окном. Хуже того, текст титра и вовсе не
  принадлежит событию: он часть строки-адреса МЕДИА, общей на все места
  использования, — то есть «поменять заголовок во втором выпуске» физически
  некуда записать. Заметка F-TXT-002 три раунда назад назвала это точно
  («шаблон — это вложенная композиция с публичным набором параметров»), но
  вынесла вердикт «не берём» с обоснованием «вложенных секвенций у нас нет
  ВООБЩЕ». Вложенность сделана в Р.50-Р.58 — посылка вердикта снята.
* **П.2.** «Костыли вместо системного» — точный диагноз, и вот его форма:
  параметр у нас это ПОЛЕ ВАРИАНТА перечисления, паспорт статический
  (`&'static`), адресация по строке, а анимируемы ровно три носителя из
  десятка. Всё, что не число, — не свойство: флаги, списки, цвета (лежат
  тройками чисел), текст, ссылка на медиа рисуются вручную в своих окнах.
  Плагин в такую систему не встраивается ни одним способом: его паспорт
  известен только в рантайме.
* **П.3.** Физика — не «ещё один эффект», и это главная находка раунда.
  Видео-путь у нас СТРОГО без состояния: кадр есть чистая функция времени, и
  ровно на этом стоят пост-FX мемоизация, кэш на видеокарте и детерминизм
  (инвариант 11). Симуляция зависит от истории и это свойство отменяет. Ответ
  не «завести состояние», а «сделать симуляцию функцией»: считать её от начала
  события фиксированным шагом, тогда состояние на кадре снова однозначно.
  Попутно: генератор сегодня видит только своё время и НЕ ЗНАЕТ скорости
  события — а именно от неё владелец хочет, чтобы буквы падали. Скорость живёт
  в движке и должна доехать до генератора числами.
* **П.4.** Требование ноля цены не новое, а уже действующее правило («ничто в
  горячем пути не смеет быть O(всего монтажа)»), и у звука оно исполнено
  идеально: без кривых — ни одной лишней операции. У видео — наполовину:
  событие без кривых ничего не платит, а вот событие С кривыми клонирует всю
  цепочку эффектов на каждый кадр и ищет параметры сравнением строк.

### Решения владельца (AskUserQuestion)

* **Объём — ФУНДАМЕНТ**: заметки в базу фич, модель свойств, параметры
  генераторов на событии с автоматизацией, публичные параметры композиции с
  переопределениями. Выражения, физика и плагины — только заметки и
  интерфейсы. Варианты «вместе с выражениями», «вместе с физикой» и «только
  бумага» отвергнуты.
* **Параметры генераторов — НА СОБЫТИЕ**, как у эффектов. Медиа остаётся видом
  генератора и кэш-полоской (решение Р.53 в силе), «править во всех местах
  разом» становится отдельной командой.
* **Плагины — все три модели сразу в интерфейсах**, порядок внедрения:
  встроенные, потом динамические библиотеки, OpenFX возвращаем позже. Вердикт
  F-EXT-001 («отвергнуто») этим пересматривается ЯВНО.
* **Выражения — своя мини-формула, считается вживую** на каждом кадре;
  внешних интерпретаторов нет.
* **Типы публичных параметров сразу**: число, текст, цвет, флаг, выбор, медиа;
  кривые — у числа и цвета, остальное меняется ступенькой.
* **Имена публичных параметров — свободный текст автора.** Это содержимое
  проекта, как имя события, а не текст программы.
* **Экземпляр переопределяет только ОПУБЛИКОВАННОЕ**, значением или кривой.
  Вариант «любое свойство внутри по адресу» отвергнут: шаблон потерял бы
  интерфейс и ломался бы при правке внутри.
* **Физика — симуляция от начала события фиксированным шагом**, состояние на
  кадре есть чистая функция; физика даёт генератору ЧИСЛА, а не пиксели.

## Раунд Р.60 (2026-09-22): параметризация композиций — «кривых автоматизаций я нигде не вижу»

Претензия владельца, дословно:

> По поводу фазу параметризации композиций:
> Параметризация композиций сделана странно, я вот поставил эффект-прокинул
> параметр на ружу, и внезапно обнаружил что я могу в разных местах поставить
> разные значения и будет что-то типо автоматизации кривых. При этом в окне
> параметров есть только сами поля - но кривых автоматизаций я нигде не вижу.
> Это очень странно. Да кривые автоматизации нужны, но как такая ошибка вообще
> дошла? Там ни одной кнопки в окне про автоматизацию нет. Еще значения min max
> всегда в 0 проставляются по умолчанию, что странно, можно и другие умолчания
> проставлять.

### Что показала разведка (владелец прав по обоим пунктам)

* **Скрытый режим записи автоматизации.** В окне «Параметры композиции» у
  числовой ручки стоял безымянный глиф `+`. Он заводил кривую с ОДНИМ ключом под
  курсором, и дальше каждая правка поля клала новый ключ в позиции курсора
  (`bound_apply` с `key = None`). Ни графика, ни таблицы ключей, ни подсказки в
  окне не было — «поставил разные значения в разных местах» и есть эта запись.
  Это ровно тот дефект, который закрывало решение Р.34 «один механизм анимации
  на всё»: у слота эффекта и у генератора кривые рисует общий виджет, а окно
  экземпляра его обошло и завело второй, невидимый.
* **«Как такая ошибка вообще дошла».** Тест t683 утверждал, что «число с кривой
  садит ключ в материале экземпляра», и был зелёным — он проверял МОДЕЛЬ, а не
  то, что человек видит на экране. Урок Р.40 («тест утверждает наблюдаемое
  следствие и щупает из точки, откуда действует человек») к этому окну применён
  не был. Отсюда сторож t693: список окон, где значение правится по времени,
  и требование, чтобы каждое ходило через общий виджет.
* **Ноль в пределах.** `PubRange` хранит сужение как `Option<f64>`, а поле
  рисовало пустое значение как `0.0`. При этом у цели уже есть свой паспорт
  (`ParamSpec.min/max/default`), и именно он — законное умолчание. Паспорта «по
  адресу» в модели не было вовсе: были `addr_type` и `addr_value`, но не
  `addr_spec`.

### Решения раунда

* **Кривые переопределений показывает ТОТ ЖЕ виджет**, что у слота и генератора
  (`automation::draw`): график ↔ таблица, активная кривая, ключ по курсору,
  общий замок оси. Своего редактора ключей у окна экземпляра не будет.
* **Кривая заводится названным действием** «+ кривая» в секции «Автоматизация»,
  пункт меню — имя ручки автора дословно. Безымянный глиф убран.
* **Ключ по курсору пишется только у ВИДИМОЙ кривой**; у ручки без кривой правка
  поля — константа. Скрытой записи не остаётся по построению.
* **Пределы ручки по умолчанию — паспорт цели** (`Project::addr_spec`). В файл
  пишется только СУЖЕНИЕ: значение, равное пределу цели, хранится как `None`.
  Сброс к пределам цели — одно действие. Значение у потребителя зажато пределами
  цели, а поверх них — сужением автора (было `±1e9`).
* **Копии пределов в публикации не будет** — по той же причине, по которой не
  хранится значение шаблона (Р.59): копия разошлась бы с целью при первой правке.

>    "disabled" - в коде есть какое-то состояние буфера обмена - что плохо, нужно по

>    или задать формулу генерации от времени, а можно и отдельную кривую сконфигурировать
>    по своему, другим типом, и т.д.

Плюс прежние разрешения: «Обратной совместимости не надо», «По любым пунктам могу быть не
прав, задавай вопросы где я не прав и по тонким моментам, не ограничивайся в вопросах»,
«Делай важные заметки для агентов, тесты и т.д. чтобы не возвращаться к однотипным
проблемам».

### Что показала разведка

* **Буфер обмена — владелец прав по косвенному признаку.** Кнопка «Вставить огибающую»
  умеет гаснуть, и это правда означало состояние внутри программы: копирование пишет И в
  системный буфер, И в зеркало `env_clipboard`, а доступность кнопки решается по зеркалу.
  Скопированное в другом окне программы вставить нельзя. Второй половиной того же места
  кнопка гаснет при другом виде эффекта — то есть ремаппинг не просто отсутствует, а
  запрещён.
* **Форма сегодня одна на всю кривую** — булево `ease` со сглаживанием `smoothstep01`.
  Просьба «формы отрезков» ломает это поле целиком, что при «обратной совместимости не
  надо» законно.
* **Место под источники заложено заранее.** `CurveSource` с вариантами `Keys`/`Formula`/
  `Link` существует с Р.59 и сегодня отвергается валидацией громко: заводился именно для
  того, чтобы вычислитель приехал следующим раундом, не ломая формат.
* **Три заметки базы фич уже написаны под это** (F-AUT-007 выражения, F-AUT-008 связь,
  F-AUT-009 формы отрезка), и одна из них с владельцем спорит — см. ниже.

### Где владелец разошёлся с разведкой (и решил сам)

Заметка F-AUT-009 утверждала, что **зигзаг — не форма отрезка, а другой ИСТОЧНИК
значения**: «зигзаг, заданный числом периодов, ключами не выражается вовсе, и пытаться
впихнуть его шестым видом в закрытый список — прямой путь к Smooth 2». Владелец решил
иначе: зигзаг — форма на отрезке между двумя соседними ключами. Причина: у зигзага между
двумя ключами есть начало и конец, заданные ключами, а источник описывает кривую ЦЕЛИКОМ и
ключей не имеет вовсе; смешивать их значило бы требовать формулу там, где человек хочет
«вот на этом куске подрожи».

Следствие, которое заметка предсказала верно и которое принято вместе с решением: **у
формы обязан быть свой набор параметров, а не одно число жёсткости.** Поэтому форма —
перечисление с данными, и шестой вид не ломает ни файл, ни экран.

### Решения владельца (AskUserQuestion)

* **Объём — три стадии одним раундом**: формы отрезков и буфер, потом связь, потом
  формула. Порядок из заметок: связь раньше формулы, потому что формула без адресата
  вырождается в дорогой способ нарисовать кривую мышкой.
* **Зигзаг — ФОРМА отрезка** (пересмотр вердикта F-AUT-009 п.3, см. выше).
* **Кнопка вставки всегда активна**, по нажатию читается настоящий системный буфер, не
  разобралось — ошибка с причиной. Зеркало внутри программы удаляется.
* **Ремаппинг**: совпавшие по имени и типу поля ложатся молча, для остатка — окно
  сопоставления «кривая → параметр цели».
* **Адресация связи — любое событие проекта** (выбрано против рекомендации «только своё
  событие»). Выведенное ограничение: связь не пересекает границу ленты — наружу потому,
  что лента перестала бы быть самодостаточной и сломался бы закон Э, внутрь потому, что
  для этого уже есть публичные параметры композиции.
* **Умолчание формы для новых ключей живёт в ПРОЕКТЕ**, не в настройках машины: настройка
  машины дала бы «один файл — два поведения» (урок Vegas).
* **Нечисловое ведётся тоже** (выбрано против рекомендации «только число и цвет»): флаг —
  порогом, выбор, текст, медиа и цвет — снимками на отметках оси ЗНАЧЕНИЯ ведущего
  свойства.

### Что решено по ходу разбора

* **Амплитуда зигзага — в единицах параметра, а не долей перепада между ключами.** Самый
  частый зигзаг — дрожание вокруг ПОСТОЯННОГО значения, где перепад равен нулю: доля
  схлопнула бы фичу ровно там, где она нужна. Клампится паспортом цели.
* **Умолчание формы обязано воспроизводить сегодняшнее сглаживание побитово**, иначе
  двинутся `GOLDEN_AUDIO`/`GOLDEN_VIDEO`, а это регрессия детерминизма, а не новая
  возможность.
* **Скорость (`rate`) принимает только прямую и отказывает ГРОМКО**: замкнутая форма
  обратной карты варпа стоит на кусочно-линейном профиле. Правило уже существует для
  `ease` и просто становится шире.

Плюс прежние разрешения: «По любым пунктам могу быть не прав, задавай вопросы где я не

### Что показала разведка (владелец прав по всем трём пунктам)

* **Растяжение — не в композите, а в декодере.** `sws_scale` тянет кадр ровно в размер
  проекта, соотношение сторон источника в вызов не входит; композитор кадр «чужого размера»
  не вписывает, а отбраковывает. Ни у проекта, ни у события, ни у ленты нет поля «правило
  приведения»; ни один из регресс-тестов не подаёт материал с несовпадающими пропорциями,
  поэтому растяжение проходит зелёным. Заметка F-MED-004 замерила это ещё 08.09 и вынесла
  вердикт «берём, приоритет A, как геометрию слоя, а не как галочку».
* **Комбо режимов Pan из трёх пунктов мёртвое.** Ветки Fit и Fill побайтно одинаковы, и к
  моменту Pan аспект уже потерян; Pan — кроп-рамка в координатах источника, полей произвести
  не может по построению.
* **Как у серьёзных.** Набор правил у всех один (вписать / заполнить / растянуть / как есть),
  а УРОВЕНЬ разный: Resolve — проект (задним числом на всё), FCP — клип (двести клипов —
  двести правок), Premiere — настройка программы (не действует на поставленное), Kdenlive —
  профиль фреймворка (опция «не трогай размер» на деле добавляет эффект Transform). Два
  урока, которых нет в справках: «вписать» кладёт в кадр ЧЁРНОЕ, и на верхнем слое это
  стирает всё под собой (Pitivi #1378) — поля обязаны быть прозрачными; «как есть» — не
  отсутствие правила, а единственное, что не выдумывает пикселей.
* **Дорожки как сущности нет.** Счётчики плюс `lane: u32` у события; имя и высота вне undo.
  Аудио суммируется клипами прямо в выход, видео складывается alpha-over поклипно, у морфера
  вход пер-клиповый. Ключ «(вид, номер)» для FX-состояния не годится: вставка дорожки
  перенумеровывает соседей и убьёт состояние цепочек (инвариант 3) — дорожке нужен свой
  стабильный id (F-AUD-004, F-TL-006 это предсказали).
* **Окна настроек проекта нет** — только комбо fps/разрешение из пяти пресетов в панели
  превью; произвольного ввода нет.

### Решения владельца (AskUserQuestion)

* **Уровень правила — проект + исключение у события.** У проекта умолчание (действует
  задним числом на всех, кто ему следует), у события — «следовать проекту» либо своё.
* **Умолчание — «вписать» с ПРОЗРАЧНЫМИ полями.** Масштабирует и вверх, и вниз.
* **Геометрия — встроенный узел события, первый в цепочке, как Pan/Crop в Vegas.**
  Узел перетаскивается по цепочке (эффекты до него работают в пространстве источника, после
  — в кадре проекта), удалить ведущий нельзя, ТАКОЙ ЖЕ узел можно добавить из каталога ещё
  раз позже в цепочке. FX «Pan» (2D) упраздняется, Pan3d и CamMotion остаются эффектами и
  работают над приведённым кадром. Маски — отдельным change'ом после, но узел проектируется
  с местом под маску.
* **При постановке: первый клип в пустой проект задаёт настройки проекта** (растр, fps, если
  fps делит 90 000); дальше несовпадение НЕ спрашивает (правило UI 4), а сообщается в строке
  состояния с адресом «где изменить» (правила 16, 19).
* **Ленты получают СВОЙ растр и СВОЙ fps** (выбрано против рекомендации «только растр»).
  Это пересмотр решения Р.50 «наследовать всё» — подтверждён отдельным вопросом с названными
  следствиями: закон Э и оракул «лента == развёрнутое» действуют только при настройках,
  равных проекту; свой fps — квантование непрерывного времени ленты к её сетке (кадр
  держится, без смешения), аудио-сетка общая; экземпляр ленты приводится тем же правилом,
  что файл.
* **«Разные fps, разные цветности» источников — не в этот раунд**: завести заметки в
  docs/features (приведение частоты кадров, управление цветом) и зафиксировать «Отложено».
* **Mute и solo дорожки — содержимое проекта и действуют на экспорт** (выбрано против
  рекомендации «solo — только прослушивание»). Следствие: окно рендера обязано перечислить
  заглушённые дорожки и активное соло ДО старта (правила 16, 19), kt-cli — печатать.
* **Свойства дорожки в этот раунд — все четыре**: уровень (дБ / непрозрачность), цепочка FX
  (аудио и видео), замок, режим наложения видеодорожки.
* **Вход цепочки видеодорожки — композит её собственных событий** («дорожка = неявная
  лента»): переходы, перекрытия и фейды внутри, потом цепочка, уровень, наложение вниз;
  дорожка без FX, с уровнем 1 и обычным наложением идёт прежним путём байт-в-байт.
* **Огибающие дорожки (во времени таймлайна) — отдельным change'ом после**; сейчас значения
  статические, через паспорт свойств.
* **Два change'а**: `frame-conform-and-event-geometry` (A) и `track-object-and-track-fx`
  (B); B3 зависит от A1, поэтому A идёт первым.

### Что решено по ходу разбора

* **Контракт «декодер отдаёт ровно запрошенное качество» не меняется** — меняется, КТО
  считает запрошенное: одна функция геометрии от (натив, растр, правило, ступень) даёт и
  размер декода, и прямоугольник размещения; заказ по-прежнему равен чтению (инвариант 4).
* **Аудио-дорожка без цепочки, уровня и mute складывается в выход прежним порядком** — иначе
  двинулся бы `GOLDEN_AUDIO` от одной перестановки f32-сложений; стадия дорожки появляется

### Что показала разведка

1. **Файл не открывается — воспроизведено на этой машине**: `untitled_v26.09.19.otio` (и его
   recovery от 09.20) отвергается валидацией `RateShapeMustBeLinear(ClipId(17))`. В файле
   14 кривых `rate` записаны с `"ease": true`; читатель Р.61 разворачивает `ease` в форму
   «плавно», а валидатор скорости с Р.61 принимает только прямую. До Р.61 варп форму
   `ease` НЕ ЧИТАЛ вовсе (её читал только `cam_at`) — кривая скорости всегда звучала
   кусочно-линейно. Значит правильная миграция для `rate` — «линейно», как звучало, а
   отказ на чтении — регрессия формата (обещание «байты и звук прежних файлов не
   двигаются» нарушено, обратная совместимость чтения нужна всегда, «не надо» относилось к
   ЗАПИСИ старым читателем).
2. **«Тишина в конце» — событие потребляет больше материала, чем есть.** У paintitblack
   события 3/4 (Rolling Stones) длятся 3.3…320.3 с при rate 0.75 и потребляют 237.7 с
   материала, а файл длится 226.27 с. Последние ≈11 с события читают за концом файла;
   движок окно считает по СОБЫТИЮ (закон П — длины медиа план не знает), промах внутри
   окна = «тишина с underrun'ом». **Разведка задачи 1.1 закрыта замером:** наш kt-media
   отдаёт для этого webm ровно 226.268 с (как ffprobe) — длительность верна; а
   `trim_max_end` для незеркального события возвращает `i64::MAX / 4`, то есть предела у
   правого трима НЕТ вовсе. Край утащили вправо ещё при rate 1 (тогда перебор был 90.7 с),
   замедление уменьшило его до 11.5 с. Соседнее событие 5 (277.9 с → 208.4 с) внутри
   материала и не глючит; у MCR событие 17.6 с — потому «реже».
3. **Формулы.** Поле формулы каждый кадр перечитывает текст ИЗ МОДЕЛИ и применяет только
   законный текст: незаконченный ввод (`sin(`) стирается на следующем кадре, а первая
   законная приставка (`t`) немедленно применяется и обнуляет ключи. Вдобавок график рисует
   `c.keys`, а у формульной кривой ключи пусты до разрешения — на экране ничего.
4. **Фокус.** egui 0.36 отдаёт фокус `TextEdit` только по Esc/Tab, другому фокусируемому
   виджету или исчезновению поля; клик по таймлайну (`Sense::click_and_drag`, не focusable)
   фокус не трогает. `handle_keys` возвращается на `egui_wants_keyboard_input()` — все
   горячие клавиши мертвы до закрытия окна. Правило 14 в чек-листе есть, а общего
   механизма «клик мимо поля отдаёт фокус» нет.
5. **Меню форм.** И `menu_hit`, и `seg_hit` считаются от `hover_pos()` КАЖДЫЙ КАДР, а
   содержимое `context_menu` перерисовывается каждый кадр: указатель ушёл к попапу —

   назван.
6. **Геометрия.** `EventGeometry` — правило, кроп 4 стороны, позиция, зум, поворот, якорь;

7. **Дорожки** — версия 04c1133 это архив change A, change B (дорожка-объект) в ней ещё

11. **Вход при публикации** — `Command::PublishParam` правит ТЕКУЩУЮ ленту, поэтому

12. **Окно параметров экземпляра** — отдельное `InstParamsWin`; у события-генератора

13. **Underrun'ы** — по флайт-логу с 3501.8 с сессии каждый прыжок (817, 528, 539, 500,

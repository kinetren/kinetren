# Формат проекта: OpenTimelineIO (.otio)

Родной формат — OTIO (JSON, эталон — библиотека OpenTimelineIO 0.18.x).
Реализация — крейт `src/libs/kt-otio` (чистый Rust, см. его CLAUDE.md).
Решения раунда Р.24 — docs/user-feedback.md; каталог тонкостей — пп.135–153
в docs/porting-notes.md.

Старый `.ktproj` — ТОЛЬКО импорт («Файл / Импортировать .ktproj…» или
`kt-cli convert`): перекрытия конвертируются в переходы/развод (п.143),
результат живёт как .otio, исходник не изменяется. Писателя ktproj в кодовой
базе больше нет.

## Слой OTIO (совместимость с другими программами)

- Файл = один `Timeline.1`; дорожки — `Track.1` (`kind: Video|Audio`) внутри
  `tracks: Stack.1`. **Порядок видео-треков инвертирован относительно наших
  lane**: OTIO композитит поздние треки поверх ранних, у нас lane 0 — верх,
  поэтому первый видео-трек файла — нижний слой. Аудио — в прямом порядке
  после видео.
- Клип — `Clip.2`: `source_range` (in-point + длительность),
  `media_references["DEFAULT_MEDIA"] = ExternalReference.1` с `target_url`
  (относительный путь от файла проекта; не релятивизуется — абсолютный
  `file://` URL; `synth:<pattern>` — тестовые источники, verbatim).
- Генератор (Р.52) — медиа с путём `gen:<вид>[:<ключ>=<знач>]*` (канон:
  нижний регистр, умолчания не пишутся, цвет одним токеном `c=rrggbb`;
  словарь — `kt_model::GeneratorKind`). В файле его клип несёт
  `GeneratorReference.1`: `generator_kind = "kt.<вид>"`, `parameters` —
  поля вида, `available_range` ОБЯЗАТЕЛЕН (0 .. source_in+duration, rate
  90000 — у генератора длительности нет, но формат требует её назвать).
  ЧУЖОЙ `generator_kind` (не `kt.*`) не типизируется: passthrough +
  заметная заглушка. Версию файла генератор НЕ поднимает: старая сборка
  видит заглушку вместо кадра, а узел возит verbatim — молчаливой порчи
  нет. Неиспользуемый генератор в бине едет путём в `kt.bin_media`.
  **Р.53 (пп.419-424)** добавила виды `transparent`, `rect`, `ellipse`,
  `line`, `leader`, `table` (разновидность — поле `table`), `window` и
  поля анимации титра `anim`/`anim_secs`. Версию файла это по-прежнему НЕ
  поднимает по той же причине: незнакомый `generator_kind` старая сборка
  показывает заглушкой и возит verbatim, а незнакомые поля `parameters`
  игнорирует serde. Файлы С ТИТРАМИ при пересохранении прирастут ключами
  `anim`/`anim_secs` (сериализуются все поля) — идемпотентность цела,
  байт-стабильность именно таких файлов не обещана.
- Зазоры — `Gap.1`. **Хвостовой зазор задаёт монтажную длину** и пишется:
  дорожка короче конца таймлайна дополняется им (Р.25 — иначе чужой монтаж
  после нашего сохранения становился короче). Длина читается в
  `Project.timeline_end`, рендер доходит до неё чёрным/тишиной.
  Пустая дорожка, которой не было в исходном файле, не пишется.
- Переход — `Transition.1{ in_offset, out_offset, transition_type }` между
  соседними клипами; тот же объект ПЕРВЫМ/ПОСЛЕДНИМ ребёнком дорожки или
  рядом с `Gap` — это фейд-ин/фейд-аут (Р.25): эталон подставляет
  отсутствующему соседу Gap, и мы рендерим уход в прозрачность/тишину.
  Наружу `transition_type` осмысленный (Р.33, п.222): кроссфейд —
  `SMPTE_Dissolve`, вайпы/маски — `SMPTE_Wipe`, остальное — `Custom`;
  чужой тип импортируется кроссфейдом (notice) и пишется обратно
  нетронутым. Наши данные — в `Transition.metadata.kt`:
  `kind` (вид с параметрами, internally tagged), `audio` (кривая
  аудио-кроссфейда, не пишется при equal-power), `auto` (кривые
  параметров вида, тики от начала окна), `invert` (инверсия Р.51,
  пишется только true). Возврат к обычному кроссфейду ВЫЧИЩАЕТ конверт.
  НАЛОЖЕННЫЙ переход (Р.51, п.399) ребёнком трека невыразим (его пара
  лежит в соседних Track карты слоёв) — он едет списком
  `overlap_transitions` в конверте своей ленты: `[{a, b, kind?, audio?,
  auto?, invert?}]`, офсетов нет (окно — сама зона перекрытия), id
  назначается на чтении.
- Метки — `Marker.2` на корневом Stack: `marked_range` (диапазонная метка,
  п.141-142; точечная = нулевая длительность), `color` (наши пишутся GREEN
  по умолчанию, чужой цвет возится round-trip).
- FX — стандартные `Effect.1` в `effects` клипа: `effect_name = "kt:<kind>"`,
  `enabled = !bypass`, параметры (типизированный `FxInstance`) — в
  `metadata.kt` эффекта. Реверс клипа — `LinearTimeWarp.1{time_scalar: -1}`
  ПЕРВЫМ в цепочке (FX применяются после реверса). Чужой скаляр ≠ ±1 не
  рендерится (notice + passthrough).
- Время — `RationalTime{value, rate}`. Наши файлы пишут rate=90000 (тики,
  целые значения точны в double); чужие rate квантуются к сетке тиков.

### Passthrough

Непонятое сохраняется и пишется обратно: неизвестные поля известных схем —
на своих местах; объекты неизвестных схем/версий-листьев — verbatim (на
таймлайне — серый плейсхолдер: занимает место, удалить можно, двигать
нельзя); чужие неймспейсы `metadata` — нетронуты. Версия ХРЕБТА
(Timeline/Stack/Track) новее поддерживаемой — честный отказ. Байт-гарантия —
идемпотентность: `save(load(save(x))) == save(x)`; первое сохранение чужого
файла нормализует форматирование (как эталон). Привязка остатков: клипы — по
ClipId, дорожки/gap'ы/переходы — по позиции на момент загрузки
(ограничение v1).

## Слой `metadata.kt` (наши данные; версия — `kt.v`, сейчас 7)

Версия у файла ОДНА (на Timeline) и ставится ПО СОДЕРЖИМОМУ: файл без
новшеств пишется младшей версией и остаётся байт-стабильным; файл новее
поддерживаемой — честный отказ `KtMetaTooNew` (старая сборка молча
испортила бы монтаж). Что поднимает версию:

| v | Что появилось |
|---|---|
| 2 | камеры и камерные дорожки; автоматизация FX (Р.29–Р.30) |
| 3 | кривые в тиках материала; выключатели; вид перехода и кривая аудио (Р.33) |
| 4 | морфер-СЛОЙ и именованные области (Р.35) |
| 5 | кривые и сила морфер-слоя (Р.38) |
| 6 | вложенные секвенции (Р.50) |
| 7 | переходы Р.51: `invert` и наложенные (`overlap_transitions`) |

На `Timeline.metadata.kt`:

| Ключ | Что |
|---|---|
| `v` | версия конверта; новее поддерживаемой → отказ загрузки |
| `settings` | `{fps, width, height, sample_rate}` |
| `transport` | `{region: [start, end] в тиках, loop_enabled}` — вне undo |
| `ui` | `UiState` (вьюпорт/курсор/lane_order/meters_w; `lane_names` — только morph: имена v/a-дорожек живут в `Track.name`; bin-поля — отдельными ключами ниже) |
| `bin_media` | медиа НЕ на таймлайне: `[{id, path}]` (пути как target_url) |
| `bin_groups` / `bin_layout` / `bin_free` | раскладка медиа-бина |
| `end` | монтажная длина в тиках, если она больше материала (хвостовой Gap) |
| `lanes` | число наших дорожек `[видео, аудио]` — пустые в файл не пишутся |
| `layers` | слои переслаивания: `{video: [n…], audio: [n…]}` — сколько подряд идущих `Track` занимает каждая дорожка (перекрытие внутри одного трека в OTIO невыразимо), плюс `off` при выключенной опции |
| `morph_lanes`, `morphers` | morpher-система (движок видит только effective_clips) — morph-дорожки НЕ треки OTIO; морферы отсортированы по MorphId |
| `sequences` | сайдкары вложенных лент (Р.50): дорожки/порядок/морферы/камеры/карта слоёв каждой; тело ленты инлайнится `Stack`-ом в каждый экземпляр |
| `overlap_transitions` | наложенные переходы КОРНЕВОЙ ленты (Р.51, п.399): `[{a, b, kind?, audio?, auto?, invert?}]`; у вложенных — то же поле в их сайдкаре |

На `Clip.metadata.kt`: `{id, media, link_group?, gain?}` — наши числовые
идентификаторы (стабильность undo/морферов/линков) и громкость клипа
(стандартного места в OTIO нет). Чужой файл без kt получает id
детерминированно (п.153).

На `Effect.metadata.kt`: полный `FxInstance` (internally tagged,
`{"kind": "...", ...параметры плоско}`).

Схема переиспользуемых типов (`FxInstance`, `MorpherEvent`, `UiState`,
`BinGroup`) — serde-derive живой модели kt-model; её дрейф ловят
байт-golden'ы `src/fixtures/demo-legacy-import.otio` (т.148) и тесты
kt-otio (т.144–154). Конформанс с эталонной python-библиотекой — т.149;
кросс-рендер против melt (MLT) на чужих сэмплах — т.158
(`src/fixtures/otio-samples`, оба gated по наличию инструментов).

## Ограничения v1 (документированы, не реализованы)

`SerializableCollection`-корень (несколько таймлайнов) —
отказ; бандлы `.otioz`/`.otiod` — не поддерживаются; цвет метки в UI не
редактируется (только round-trip); notices импорта показываются на
английском (каталогизация — будущий раунд).
